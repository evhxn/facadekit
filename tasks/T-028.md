# T-028 – Frame, render and FPP routes

- **Milestone:** MVP
- **Recommended model:** Sonnet
- **Depends on:** T-019, T-022, T-024
- **Parallel with:** T-025, T-026, T-027

## Goal

Expose over HTTP: the authoritative composited frame at a time, starting renders as jobs, listing and downloading renders, probing an FPP, publishing a render to FPP as a job, and reading FPP status.

## Files to create or modify

- Create `studio/backend/src/facadekit/api/routes_render.py`, `api/routes_fpp.py`
- Modify `api/app.py` (include routers)
- Create `studio/backend/tests/test_api_render_fpp.py`

## Interfaces (copied from docs/05-interfaces.md)

Available:

```python
Compositor(project, project_dir, *, scale=1.0); .frame(t_ms) -> BGR uint8; .close()
render_project(project_dir, preset_id, out_path, *, include_audio=True, progress=None, cancel=None)
    -> {"filename", "size_bytes", "duration_ms", "frames"}          # FkError UNKNOWN_PRESET / CANCELLED
render_alignment_check(project_dir, out_path, *, seconds=20, preset_id="pi3-1080p30") -> same dict
get_preset(id)                                                       # FkError UNKNOWN_PRESET
probe_fpp(host) -> {"reachable", "version", "major", "ok", "problems"}
publish_render(host, local_path, *, media_name, playlist_name, start, sequence_name=None, progress=None, cancel=None)
    -> {"media_name", "playlist_name", "started"}
FppClient(host).status() -> {"status_name", "current_playlist", "seconds_played"}
AppState: store (load/save/project_dir), jobs (submit), events
new_id("rnd")
```

Routes (prefix `/api/v1`):

| Method and path | Request | Response |
|---|---|---|
| `GET /projects/{pid}/frame?t_ms=<int>&scale=<0.1..1>` | – | `image/jpeg` authoritative composited frame (`scale` default 0.5) |
| `POST /projects/{pid}/renders` | `{"preset": str, "include_audio": bool, "kind": "show"\|"alignment_check"}` | 202 `{"job_id": str}` |
| `GET /projects/{pid}/renders` | – | `[{"render_id": str, "filename": str, "size_bytes": int, "modified_at": str}]` newest first |
| `GET /projects/{pid}/renders/{rid}/file` | Range | `video/mp4` |
| `POST /fpp/probe` | `{"host": str}` | `{"reachable": bool, "version": str\|null, "major": int\|null, "ok": bool, "problems": str[]}` (never an HTTP error for an unreachable host) |
| `GET /fpp/status?host=` | – | `{"status_name": str\|null, "current_playlist": str\|null, "seconds_played": number\|null}` |
| `POST /projects/{pid}/publish` | `{"host": str, "render_id": str, "playlist_name"?: str, "start": bool, "sequence_name"?: str}` | 202 `{"job_id": str}` |

Job results: render `{"render_id": str, "filename": str, "size_bytes": int, "duration_ms": int}`; publish `{"media_name": str, "playlist_name": str, "started": bool}`.

Renders are stored at `renders/<render_id>.mp4` in the project folder; `render_id` matches `^rnd_[0-9a-f]{8}$`. Alignment-check renders use the id form `rnd_<8 hex>` too and are distinguished only in the publish names.

Default publish names: media `fk_<project_id>.mp4`, playlist `FacadeKit - <project name>`. When the render came from `kind="alignment_check"`: media `fk_<project_id>_align.mp4`, playlist `FacadeKit - <project name> (alignment)`. To know the kind later, write a sidecar `renders/<render_id>.json` containing `{"kind": …, "preset": …}` when the render job finishes.

## Steps

1. Frame route: validate `0 <= t_ms`, `0.1 <= scale <= 1` (422 `BAD_REQUEST`). Build a `Compositor`, get the frame, close it, JPEG-encode at quality 85. Header `Cache-Control: no-store`. Creating a compositor per request is acceptable for the MVP (it is used only when paused).
2. Render route: validate the preset with `get_preset` before submitting (422 `UNKNOWN_PRESET`). The job calls `render_project` or `render_alignment_check` with the job's `progress`/`cancel`, writes the sidecar, returns the result with `render_id`.
3. The render job reads `project.json` from disk at start; the UI saves before requesting a render.
4. Publish route: validate `render_id` and that the file exists (`NOT_FOUND`) before submitting. After a successful publish, store `host` and the playlist name in `project.fpp` (load, modify, save with one retry on `REVISION_CONFLICT`) and publish a `project` event.
5. `GET /fpp/status`: wrap `FppClient(host, timeout=3).status()`; on `FkError` return all-null fields (the UI polls this; errors must not spam).
6. All handlers are sync `def`.

## Pitfalls

- `host` comes from user input and is used to make HTTP requests from the user's own machine to their own network. That is the feature, but reject hosts containing `/`, `?`, `#`, `@` or whitespace (`BAD_REQUEST`) so the value cannot smuggle a path or credentials.
- Do not delete old renders automatically.

## Acceptance

```
cd studio/backend && uv run pytest -q tests/test_api_render_fpp.py && uv run mypy src && uv run ruff check .
```

Tests (`client` fixture, `fake_fpp` fixture, a 320×180 project with one image clip built through the API: create project, upload a PNG, PUT project with a surface and clip, timeline 1000 ms):

- `GET /frame?t_ms=0&scale=1` → JPEG decoding to 320×180 with the clip colour at the surface centre. `scale=5` → 422.
- `POST /renders {"preset":"preview-540p","include_audio":true,"kind":"show"}` → job succeeds; `GET /renders` lists one entry; `GET …/file` returns bytes starting with an MP4 `ftyp` box (`content[4:8] == b"ftyp"`), and a Range request returns 206.
- Unknown preset → 422 `UNKNOWN_PRESET`.
- `kind="alignment_check"` job succeeds.
- `POST /fpp/probe {"host": fake.host}` → `ok true`; closed port → 200 with `reachable false`.
- Publish the show render to the fake with `start=true` → job succeeds; the fake has `videos/fk_<pid>.mp4` and is playing `FacadeKit - <name>`; the project's `fpp.host` is now set.
- Publish the alignment render → media name ends `_align.mp4`.
- Publish with an unknown `render_id` → 404. Host `"a/b"` → 422.
- `GET /fpp/status?host=<fake>` → `status_name` `playing`; with a closed port → all nulls, HTTP 200.
