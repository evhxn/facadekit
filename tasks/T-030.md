# T-030 – Projector page

- **Milestone:** MVP
- **Recommended model:** Sonnet
- **Depends on:** T-002 (protocol below; pairs with backend ticket T-026)
- **Parallel with:** T-029, T-031

## Goal

Build the browser page that the user drags onto the projector display and makes fullscreen. It connects to the backend over WebSocket and displays exactly what it is told (calibration images pixel-for-pixel, test patterns, surface outlines), acknowledging each update.

## Files to create or modify

Under `studio/web/src/projector/`: `ProjectorPage.tsx` (replace the placeholder), `projectorSocket.ts`, `draw.ts`, `ProjectorPage.module.css`, tests `draw.test.ts`, `projectorSocket.test.ts`.

## Protocol (copied from docs/05-interfaces.md §9.2)

WebSocket URL: `ws(s)://<location.host>/ws/projector`.

Client → server:

```json
{"type": "hello", "width": 1920, "height": 1080, "dpr": 1}      // CSS innerWidth/innerHeight and devicePixelRatio
{"type": "ack", "seq": 17}                                       // after the content for seq has been on screen for 2 animation frames
```

Server → client (each has an increasing integer `seq`):

```json
{"type": "image", "seq": 17, "url": "/api/v1/projector/image/17.png"}     // draw 1:1, no smoothing
{"type": "blank", "seq": 18}
{"type": "white", "seq": 19}
{"type": "grid", "seq": 20}                                               // 1 px white lines every 120 px + border
{"type": "outlines", "seq": 21, "width": 1920, "height": 1080,
 "surfaces": [{"id": "srf_1", "name": "Garage door", "quad": [[10,10],[100,10],[100,80],[10,80]], "selected": true}]}
{"type": "compositor", "seq": 22, "project_id": "garage-2026"}
{"type": "transport", "seq": 23, "playing": true, "t_ms": 1200, "revision": 4}
```

A close with code 4000 means another projector page took over: show "Another projector window is active" and do not reconnect.

## Specification

1. Layout: a single `<canvas>` filling the viewport, black background, `cursor: none` while fullscreen, no scrollbars. The canvas backing size is **physical pixels**: `canvas.width = Math.round(innerWidth * devicePixelRatio)`, same for height; CSS size 100 vw × 100 vh; CSS `image-rendering: pixelated`.
2. Before fullscreen, show an overlay (HTML above the canvas): "Drag this window to the projector, then click here" and a big button calling `document.documentElement.requestFullscreen()`. Also show the detected physical size, e.g. "1920 × 1080 (scale 1)". Hide the overlay while `document.fullscreenElement` is set. Pressing Esc leaves fullscreen and shows it again.
3. On socket open, on `resize`, on `fullscreenchange`, and when `devicePixelRatio` changes: resize the canvas, send `hello`, and redraw the last message.
4. Drawing (`draw.ts`, pure functions taking a `CanvasRenderingContext2D` and the canvas size so they are unit-testable):
   - `drawBlank`, `drawWhite`: fill black / white.
   - `drawGrid(ctx, w, h)`: black background; 1 px white lines at every multiple of 120 px in x and y; 1 px white border; a 3 px red cross at the exact centre. Lines must sit on whole pixels (use `fillRect`, not stroked paths, to avoid anti-aliasing).
   - `drawImage(ctx, img, w, h)`: `ctx.imageSmoothingEnabled = false`; `ctx.drawImage(img, 0, 0)` with no scaling. If the image size differs from the canvas size, still draw unscaled at 0,0 (the backend checks sizes).
   - `drawOutlines(ctx, msg, w, h)`: black background; scale factor `w / msg.width` applied to points; each quad stroked 3 px white (selected: yellow `#ffff00`), a filled 8 px circle on the first corner (top-left), the surface name centred in the quad in white 24 px sans-serif.
5. Ack rule: after drawing for a message, wait for two `requestAnimationFrame` callbacks, then send `{"type":"ack","seq"}`. For `image`, first `await` image load and `img.decode()`. If the image fails to load, do not ack (the backend times out and reports it).
6. `compositor` and `transport` messages: for this ticket, draw the text "Live preview" (the WebGL compositor is attached by T-033) and ack. Structure the code so a later ticket can plug in a renderer: export `interface LiveRenderer { start(projectId: string, canvas: HTMLCanvasElement): void; transport(msg): void; stop(): void }` and a module-level `setLiveRenderer(r)` hook.
7. `projectorSocket.ts`: `connectProjector(handlers): { close(): void; sendHello(w, h, dpr): void; ack(seq): void }` with automatic reconnect (1 s backoff) except after close code 4000. A small status dot in the overlay shows connected / reconnecting.

## Pitfalls

- Browser zoom changes `devicePixelRatio`; that is why the page reports `innerWidth` and `dpr` and lets the backend verify the product equals the projector's native size.
- Do not use CSS transforms or `object-fit`; any scaling destroys the calibration patterns.
- `requestFullscreen` must be called from a user gesture (the click handler).
- Keep the canvas 2D context for these modes; the WebGL compositor (T-033) uses its own canvas element layered on top, so do not mix contexts on one canvas.

## Acceptance

```
cd studio/web && pnpm lint && pnpm typecheck && pnpm test
```

Tests (jsdom has no real canvas: test `draw.ts` against a mock context that records calls; test the socket with a fake `WebSocket` class):

- `drawGrid` on 240×120 records `fillRect` calls for vertical lines at x = 0, 120 and the right border, horizontal at y = 0 and bottom, each 1 px thick.
- `drawOutlines` scales points by `w / msg.width` (use 960 vs 1920 → 0.5) and uses yellow for the selected surface.
- `drawImage` sets `imageSmoothingEnabled` false and calls `drawImage(img, 0, 0)` with exactly three arguments.
- Socket: on open sends `hello`; on a `blank` message the handler is called and after two rAF ticks (use fake timers / a stubbed `requestAnimationFrame`) an `ack` with the same `seq` is sent; close code 4000 does not reconnect, other codes reconnect after 1 s.

Manual check (document in the PR): run backend + `pnpm dev`, open `/projector`, click fullscreen, then `curl -X POST localhost:8137/api/v1/projector/show -H 'content-type: application/json' -d '{"mode":"grid"}'` shows the grid.

## Out of scope

The WebGL live compositor (T-033), Window Management API auto-placement on the projector screen (nice-to-have, v1), any controls on this page.
