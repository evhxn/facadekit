# T-021 – FPP REST client

- **Milestone:** MVP
- **Recommended model:** Sonnet
- **Depends on:** T-003, T-020

## Goal

Implement the only module that speaks HTTP to Falcon Player (FPP): version probe, chunked file upload, playlist save/start/stop, and status.

## Background

FPP runs on the user's Raspberry Pi on the home network, usually reachable as `fpp.local` or an IP address, plain HTTP on port 80, no authentication by default. Several response details are unconfirmed assumptions (marked [A]); parse defensively. If `spikes/S-1-fpp-contract.md` exists, follow it where it disagrees with this ticket and mention that in the commit message.

## Interfaces (copied from docs/05-interfaces.md)

```python
@dataclass
class FppVersion:
    version: str          # e.g. "10.4"
    major: int
    minor: int
    branch: str

class FppClient:
    def __init__(self, host: str, *, timeout: float = 10.0) -> None: ...   # base URL http://{host}
    def version(self) -> FppVersion: ...                 # FkError FPP_UNREACHABLE / FPP_BAD_RESPONSE
    def system_info(self) -> dict[str, Any]: ...
    def list_files(self, dir_name: str) -> list[str]: ...
    def upload(self, dir_name: str, local_path: Path, remote_name: str,
               progress: Callable[[float, str], None] | None = None,
               cancel: Callable[[], bool] | None = None) -> None: ...     # FkError FPP_UPLOAD_FAILED
    def media_duration(self, name: str) -> float | None: ...              # seconds, None if unknown
    def put_playlist(self, name: str, entries: list[dict[str, Any]]) -> None: ...
    def start_playlist(self, name: str) -> None: ...
    def stop(self) -> None: ...
    def status(self) -> dict[str, Any]: ...              # {"status_name": str|None, "current_playlist": str|None, "seconds_played": float|None}
    def close(self) -> None: ...
```

FPP contract:

| Purpose | Request | Response used |
|---|---|---|
| Version | `GET /api/fppd/version` | JSON `version` (string), `majorVersion` (int), `minorVersion` (int), `branch` |
| System info | `GET /api/system/info` | JSON object, returned as is |
| List files | `GET /api/files/{DirName}` | `{"status":"ok","files":[{"name":…}]}` [A]; also accept a bare list of objects or of strings |
| Upload start | `POST /api/file/{DirName}` with empty body | 2xx |
| Upload chunk | `PATCH /api/file/{DirName}`, headers `Upload-Name: <name>`, `Upload-Offset: <byte offset>`, `Upload-Length: <total bytes>`, `Content-Type: application/offset+octet-stream`; body = raw chunk of 8 MiB | 2xx per chunk |
| Media duration | `GET /api/media/{name}/duration` | number of seconds under `[name]["duration"]` or top-level `"duration"` [A]; 404 → `None` |
| Save playlist | `POST /api/playlist/{PlaylistName}` JSON body below | 2xx |
| Start playlist | `POST /api/playlist/{PlaylistName}/start` | 2xx |
| Stop | `POST /api/playlists/stop` | 2xx |
| Status | `GET /api/fppd/status` | read `status_name`, `current_playlist.playlist`, `seconds_played`; every field optional [A] |

Playlist body sent by `put_playlist(name, entries)`:

```json
{"name": "<name>", "mainPlaylist": [ …entries… ], "playlistInfo": {"total_duration": 0, "total_items": <len(entries)>}}
```

## Steps

1. Normalise `host`: strip whitespace, a leading `http://` or `https://`, and trailing `/`. Empty → `FkError("BAD_REQUEST")`.
2. Use one `httpx.Client(base_url=f"http://{host}", timeout=timeout)`.
3. Central `_request(method, path, **kw)`: `httpx.ConnectError`, `httpx.TimeoutException` and other `httpx.TransportError` → `FkError("FPP_UNREACHABLE", f"Could not reach FPP at {host}")`. Status ≥ 400 → `FkError("FPP_BAD_RESPONSE", f"{method} {path} returned {status}")` (except where a 404 has a meaning, see table).
4. `version()`: missing `majorVersion` → try parsing `version` with regex `(\d+)\.(\d+)`; still nothing → `FPP_BAD_RESPONSE`.
5. `upload`: URL-encode nothing in headers; `remote_name` must match `^[A-Za-z0-9._-]+$` else `BAD_REQUEST`. `POST` start, then loop reading 8 MiB chunks with `PATCH`. Upload timeout per chunk 120 s. Any failure → `FkError("FPP_UPLOAD_FAILED", …)`. Report `progress(sent / total, "Uploading")` after each chunk; check `cancel()` before each chunk → `FkError("CANCELLED")`. Zero-byte file → `BAD_REQUEST`.
6. Path segments (`{PlaylistName}`, `{name}`) are percent-encoded with `urllib.parse.quote(value, safe="")` (playlist names contain spaces).
7. `status()` returns the normalised three-key dict; convert `seconds_played` with `float()` inside try/except → `None`. An empty playlist name → `None`.

## Pitfalls

- Never log or include response bodies larger than 300 characters in error messages.
- `fpp.local` (mDNS) resolution can take seconds on Windows; keep the default timeout at 10 s and do not retry in this layer.

## Acceptance

```
cd studio/backend && uv run pytest -q tests/test_fpp_client.py && uv run mypy src && uv run ruff check .
```

Tests use the `fake_fpp` fixture (`.host`, `.state_dir`, `.app` with `.state.requests`):

- `version()` → `major == 10`, `minor == 4`.
- `FppClient("127.0.0.1:9")` (closed port), `timeout=1` → `FkError` `FPP_UNREACHABLE`.
- `FppClient("http://HOST/")` normalises and works.
- Upload a 20 MiB temp file (random bytes via `os.urandom` once, repeated) → 3 PATCH requests recorded, file on the fake identical (compare SHA-256), progress ends at 1.0; `list_files("videos")` contains the name.
- `cancel` true on the second chunk → `CANCELLED`.
- `media_duration` is `60.0` after upload and `None` for a missing file.
- `put_playlist("FacadeKit - Test", [entry])` then the fake's stored JSON has `mainPlaylist == [entry]` and `playlistInfo.total_items == 1`.
- `start_playlist` then `status()["status_name"] == "playing"` and `current_playlist == "FacadeKit - Test"`; `stop()` → `idle`, `current_playlist is None`.
- `start_playlist("missing")` → `FPP_BAD_RESPONSE`.
- `upload(..., remote_name="a b.mp4")` → `BAD_REQUEST`.
