# T-204 – Camera check API, cropped snapshot, 1080p capture

- **Milestone:** v1.1 camera quality (docs/08 §3, §7)
- **Recommended model:** Sonnet
- **Depends on:** T-202, T-203
- **Parallel with:** T-205

## Goal

Give the wizard one call that answers "is this camera good enough, and where is the projection?", a zoomed snapshot of a crop, and capture at 1080p when the webcam supports it.

## Files to create or modify

- Modify `studio/backend/src/facadekit/api/routes_calibration.py` (new route), `api/routes_devices.py` (snapshot `crop`, preferred size), `api/app.py` (`sim_scene` test hook), `config.py` (camera size setting)
- Create `studio/backend/src/facadekit/models/camera_check.py`, `tests/test_api_camera_check.py`
- Web types only: `studio/web/src/api/types.ts`, `api/client.ts` (`startCameraCheck`, `cameraSnapshotUrl(id, crop?)`)

## Interfaces (new ⚑)

```python
class CameraCheck(BaseModel):
    verdict: Literal["good", "marginal", "too_coarse"]
    reasons: list[str]                    # Reason values from calib/quality.py, in rule order
    camera_width: int; camera_height: int # full frame
    lit_box: CameraRoi | None             # tight box of the projection (no margin), None if not found
    suggested_roi: CameraRoi | None       # quality.suggest_roi(...)
    px_per_proj_px: float
    proj_px_per_cam_px: float             # 1 / px_per_proj_px, rounded to 1 decimal (for the UI sentence)
    stripe_modulation: dict[str, float]   # {"2": .., "3": .., "4": ..}
    snr: float
    median_contrast: float
    controls: dict[str, bool]

POST /api/v1/projects/{pid}/camera-check   body {"camera_id": str, "roi": CameraRoi | null}  -> 202 {"job_id"}
    job kind "calibration"; result {"check": CameraCheck as dict}
GET  /api/v1/devices/cameras/{cid}/snapshot.jpg?crop=x,y,w,h      # optional; 4 non-negative ints, clamped to the frame
config.camera_size() -> tuple[int, int]   # env FACADEKIT_CAMERA_SIZE "WIDTHxHEIGHT", default (1280, 720); 1920x1080 is opt-in via FACADEKIT_CAMERA_SIZE
```

## Steps

1. Check job, following the existing scan job pattern (`state.cameras.acquire` / `release`, `CameraBusyError` → 409):
   - Open the camera, wrapped in `CroppedCamera` if `roi` is given.
   - `set_controls(auto_exposure=False, auto_wb=False, autofocus=False)` and keep the result.
   - `precheck(...)` with default `CalibSettings` and the project's projector size.
   - `probe_stripes(..., bits=(2, 3, 4))`.
   - `verdict(...)` with modulation, `p99_white` and controls.
   - Build `lit_box` and `suggested_roi` in **full-frame** coordinates (add the crop offset when a roi was given).
   - Close the camera in `finally`.
   - Errors from precheck (`CAMERA_NO_PROJECTION`, `TOO_BRIGHT`, `RESOLUTION_MISMATCH`) fail the job with their codes.
2. Snapshot `crop`: parse, clamp to the frame, slice before JPEG encoding. A malformed value gives 400 `BAD_REQUEST`.
3. Preferred size: `CameraManager._new_camera` builds `OpenCvCamera(int(id), *camera_size())`. `OpenCvCamera`'s constructor default stays 1280×720 (contract unchanged). `list_cameras` is unchanged. Invalid env values fall back to the default and log a warning.
4. Web: types and client functions only (UI is T-206).

## Pitfalls

- The check must not write to scan memory or create a calibration.
- The check moves the projector (black, white, stripes). Afterwards, show the grid again: call the same projector "show grid" path the camera step uses, so the user is not left with stripes on the house.
- `camera_size()` follows CLAUDE.md: hardware-dependent values live in config with defaults. 1080p is unverified on real webcams (spike S-3 extension).
- With the sim camera, `camera_size` is ignored (`SimCamera` has a fixed size).

Backend tests (sim app). `create_app` has no way to choose the sim scene today: add a keyword-only test hook `sim_scene: SimScene | None = None` to `create_app` (used only when `sim=True`; default keeps `default_scene()`), and build the far-scene apps with it:

- Default scene: verdict `good`, `lit_box` inside the frame, `suggested_roi` None or ≤ 60 % of the frame.
- `scene_far_too_coarse()`: verdict `too_coarse`, reasons start with `SMALL_IN_FRAME`, `suggested_roi` contains `lit_box`.
- Check with a roi equal to that suggestion gives a `lit_box` (full-frame) within 2 px of the uncropped one.
- The camera is busy during a scan → 409.
- Snapshot with `crop=10,20,100,50` returns a 100×50 JPEG; `crop=abc` → 400.
- `camera_size()` parses `"1280x720"` and falls back on `"big"`.
