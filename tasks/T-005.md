# T-005 – Project store (folder I/O)

- **Milestone:** MVP
- **Recommended model:** Sonnet
- **Depends on:** T-003, T-004
- **Parallel with:** T-006, T-007, T-008

## Goal

Read, write, list, create and delete project folders on disk with atomic writes and optimistic revision checking.

## Files to create

- `studio/backend/src/facadekit/store/project_store.py`
- `studio/backend/tests/test_project_store.py`

## Interfaces (copied from docs/05-interfaces.md)

Project folder layout:

```
<root>/<project_id>.fkproj/
├── project.json
├── media/            (created empty)
├── calibration/      (created empty)
└── renders/          (created empty)
```

```python
class ProjectSummary(BaseModel):
    id: str
    name: str
    modified_at: str            # ISO 8601 UTC mtime of project.json, e.g. "2026-11-09T21:14:03Z"

class ProjectStore:
    def __init__(self, root: Path) -> None: ...                       # root = projects_dir()
    def list(self) -> list[ProjectSummary]: ...                       # newest first; skips unreadable folders
    def create(self, name: str, projector: ProjectorSpec) -> Project: ...
    def project_dir(self, project_id: str) -> Path: ...               # FkError NOT_FOUND
    def load(self, project_id: str) -> Project: ...                   # FkError NOT_FOUND / INVALID_PROJECT
    def save(self, project: Project) -> Project: ...
    def delete(self, project_id: str) -> None: ...                    # FkError NOT_FOUND; removes the whole folder

def load_project_dir(path: Path) -> Project        # load from an explicit folder (CLI use)
def save_project_dir(path: Path, project: Project) -> None   # atomic write, no revision check
```

`save` requires `project.revision == stored.revision`, else `FkError("REVISION_CONFLICT", …)`. It writes atomically (temp file in the same folder + `os.replace`) with `revision + 1` and returns the saved project.

Already available: `facadekit.errors.FkError`, `facadekit.ids.unique_slug(name, taken)`, `facadekit.models.project.Project / ProjectorSpec / parse_project(data)`.

## Steps

1. `create`: id = `unique_slug(name, existing ids)`; make the folder and the three subfolders; write `project.json` with `revision=0`; return the project. Empty or whitespace-only `name` → `FkError("BAD_REQUEST")`.
2. `project_dir`: validate `project_id` against `^[a-z0-9][a-z0-9_-]{0,39}$` **before** touching the filesystem (prevents path traversal such as `../x`); invalid or missing → `NOT_FOUND`.
3. `load`: `json.loads` then `parse_project`. A JSON syntax error → `FkError("INVALID_PROJECT")`. If the `id` inside the file differs from the folder name, the folder name wins (users may rename folders); fix it in the returned object.
4. `save`: guard with a per-store `threading.Lock` around read-compare-write. JSON is written with `indent=2` and a trailing newline, UTF-8.
5. `list`: iterate `*.fkproj` directories; read only `name` from each JSON; sort by mtime descending.

## Pitfalls

- `os.replace` across filesystems fails; create the temp file inside the project folder.
- On Windows a file open elsewhere cannot be replaced; retry `os.replace` up to 5 times with 50 ms sleeps on `PermissionError`.
- `delete` uses `shutil.rmtree`; never accept an id that fails the regex.

## Acceptance

```
cd studio/backend && uv run pytest -q tests/test_project_store.py && uv run mypy src && uv run ruff check .
```

Tests (all in `tmp_path`): create → folder and subfolders exist, revision 0; create the same name twice → second id ends `-2`; save bumps revision to 1 and persists a changed name; saving a stale copy raises `REVISION_CONFLICT`; `load("../etc")` raises `NOT_FOUND`; corrupt JSON raises `INVALID_PROJECT`; `list` returns newest first and skips a folder with corrupt JSON; delete removes the folder; `load_project_dir`/`save_project_dir` round-trip.
