# T-025 – Asset routes (import, serve, delete)

- **Milestone:** MVP
- **Recommended model:** Sonnet
- **Depends on:** T-015, T-024
- **Parallel with:** T-026, T-027, T-028

## Goal

Let the UI import media files into a project, fetch them back (with HTTP Range so `<video>` can seek), fetch thumbnails, and delete unused assets.

## Files to create or modify

- Create `studio/backend/src/facadekit/api/routes_assets.py`
- Modify `studio/backend/src/facadekit/api/app.py` (include the router)
- Create `studio/backend/tests/test_api_assets.py`

## Interfaces (copied from docs/05-interfaces.md)

Available:

```python
AppState(store: ProjectStore, jobs: JobRunner, sim: bool); get_state(request) -> AppState      # facadekit.api.deps
store.load(pid) -> Project; store.save(project) -> Project; store.project_dir(pid) -> Path
probe(path) -> Asset            # id="" and filename="" to be filled; FkError UNSUPPORTED_MEDIA
make_thumbnail(path, kind, out_path)      # video/image only
new_id("ast")
```

Project folder: imported files live at `media/<asset_id>.<ext>` (extension lower-cased) and thumbnails at `media/<asset_id>.thumb.jpg`. `Asset.filename` is the path relative to the project folder using `/`.

Routes (prefix `/api/v1`):

| Method and path | Request | Response |
|---|---|---|
| `POST /projects/{pid}/assets` | multipart field `file` | 201 `{"asset": Asset, "project": Project}` (asset appended, revision bumped) |
| `GET /projects/{pid}/assets/{aid}/file` | supports HTTP Range | file bytes with the right `Content-Type` |
| `GET /projects/{pid}/assets/{aid}/thumb` | – | `image/jpeg` (404 for audio) |
| `DELETE /projects/{pid}/assets/{aid}` | – | `Project`; 409 `ASSET_IN_USE` if any clip or the timeline audio references it |

## Steps

1. Upload: stream the `UploadFile` to `media/<asset_id>.<ext>.part` in 1 MiB chunks, rename when complete. Extension comes from the uploaded filename; allow only `[a-z0-9]{1,5}` else use `bin`.
2. `probe` the saved file. On `FkError` delete the file and re-raise (422 `UNSUPPORTED_MEDIA`).
3. Fill `asset.id`, `asset.filename`, `asset.original_name` (basename only, max 200 chars). Make the thumbnail for video/image; a thumbnail failure is logged and ignored.
4. Load the project, append the asset, `store.save`. If the save raises `REVISION_CONFLICT` (the UI saved concurrently), reload and retry once.
5. File serving: use `starlette.responses.FileResponse`, which handles `Range` requests. Media type via `mimetypes.guess_type` with fallback `application/octet-stream`.
6. Delete: check references (`clip.asset_id` in any track, `timeline.audio_asset_id`); remove from `project.assets`, save, then unlink the file and thumbnail (ignore missing files).
7. `aid` must match `^ast_[0-9a-f]{8}$` and exist in the project → else `NOT_FOUND`. Never build a path from an unvalidated id.

## Pitfalls

- Large uploads: do not call `await file.read()` on the whole file. Because handlers elsewhere are sync, write this one as `async def` and do the disk writes with `await run_in_threadpool(...)` or small synchronous chunk writes.
- If the app runs behind the Vite dev proxy, uploads of several hundred MB must still work; no size limit in the backend.
- Verify your Starlette version's `FileResponse` returns 206 for Range requests (it does from 0.39). If the installed version does not, implement Range manually (single range only).

## Acceptance

```
cd studio/backend && uv run pytest -q tests/test_api_assets.py && uv run mypy src && uv run ruff check .
```

Tests (fixtures `client`, `sample_video`, `sample_image`, `sample_audio`):

- Upload the video → 201; `asset.kind == "video"`, `filename` starts with `media/ast_`; returned `project.assets` has one entry and `revision == 1`; the file exists on disk.
- `GET …/file` returns 200 with the full length; with header `Range: bytes=0-99` returns 206 and exactly 100 bytes.
- `GET …/thumb` returns a JPEG (`content[:2] == b"\xff\xd8"`); for the audio asset returns 404.
- Uploading a text file named `x.mp4` → 422 `UNSUPPORTED_MEDIA` and no file left in `media/`.
- Delete an unused asset → project without it, files gone. Delete an asset used by a clip (PUT a project that references it first) → 409 `ASSET_IN_USE`.
- Unknown `aid` or malformed `aid` → 404.
