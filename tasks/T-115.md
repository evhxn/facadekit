# T-115 – Automatic latency and exposure tuning for the scan

- **Milestone:** v1
- **Recommended model:** Sonnet
- **Depends on:** T-011, T-014
- **Parallel with:** T-112, T-113, T-114

## Goal

Make the laptop-driven scan faster and more reliable by measuring how long a projected image takes to appear in the camera (instead of a fixed 300 ms wait and 5 discarded frames) and by choosing camera exposure automatically.

## Files to create or modify

- Create `studio/backend/src/facadekit/calib/tuning.py`, `tests/test_calib_tuning.py`
- Modify `calib/pipeline.py` (call tuning before capture when `settings.settle_ms == 0`), `models/calibration.py` (documented below), `studio/web/src/pages/setup/StepScan.tsx` (default to automatic)

## Interfaces available

```python
ProjectorDisplay: size -> (w, h); show(image) -> None            # blocks until the image is on screen
Camera: read() -> BGR uint8; set_controls(*, auto_exposure=None, exposure=None, auto_wb=None, autofocus=None) -> dict[str, bool]
```

Convention added by this ticket: `settle_ms == 0` means "automatic". `run_calibration` then calls `measure_latency` and uses its result. The stored `calibration.json` records the values actually used.

To implement:

```python
@dataclass
class LatencyResult:
    settle_ms: int              # recommended wait after show() before capturing
    discard_frames: int         # recommended frames to discard
    frame_interval_ms: float    # measured camera frame interval

                    sleep: Callable[[float], None] = time.sleep) -> LatencyResult
def auto_exposure(display: ProjectorDisplay, camera: Camera, *, sleep=time.sleep) -> dict[str, float | bool]
    # returns {"locked": bool, "exposure": float | None, "white_p99": float}
```

## Algorithm

`measure_latency`:

1. Show black; wait 1 s; read 10 frames timing each `read()` → `frame_interval_ms` (median).
2. For each trial: show black, wait 0.7 s, record baseline mean brightness `b0`; show white (returns when displayed) and note `t_show`; read frames continuously for up to 1.5 s recording `(t, mean)`. Then show black again and do the same for the falling edge.
3. For each edge, the *settled time* is the first time after which every subsequent frame mean stays within 5 % of the final level (final level = median of the last 5 readings; the 5 % is relative to `|final − b0|`).
4. `latency = max over all edges and trials`; `settle_ms = min(1500, ceil(latency_ms * 1.3 + frame_interval_ms))`; `discard_frames = 1` (the settle wait already covers the delay; one discard flushes a stale buffered frame).
5. If white and black differ by less than 8 gray levels, raise `FkError("CAMERA_NO_PROJECTION", …)`.

`auto_exposure`: try `set_controls(auto_exposure=False)`. If refused, show mid-gray (128) for 2 s so the camera's own auto-exposure settles on a representative scene, and return `{"locked": False, "exposure": None, "white_p99": <measured under white>}`. If accepted, binary-search `exposure` in [0, 1] (6 steps) for the highest value whose 99th-percentile gray level under a white projection is below 240; return it.

`run_capture` currently contains a simple exposure loop; replace it with a call to `auto_exposure` and keep `controls_applied` semantics.

UI: the scan step sends `settings: {settle_ms: 0}` by default and shows "Tuning camera…" as the first progress message. An "Advanced" disclosure lets the user set a fixed wait (300–1500 ms) instead.

## Pitfalls

- Use the injected `clock` and `sleep` everywhere so tests can simulate time.
- Some webcams buffer 3–5 frames; that appears as latency and is handled by the measurement, which is the point of this ticket.
- Do not let tuning take more than about 12 s in total.

Tests use a `LaggyCamera` wrapper around `SimCamera` with a fake clock: each `read()` advances the clock by 33 ms and returns the frame that was current `lag_ms` earlier (keep a timestamped history of shown images by wrapping `SimDisplay.show`):

- With `lag_ms = 200`: `settle_ms` between 250 and 420, `frame_interval_ms ≈ 33`.
- With `lag_ms = 600`: `settle_ms` between 760 and 1000.
- A full `run_calibration` with `settings.settle_ms = 0` through the laggy camera at 400 ms lag succeeds with `coverage > 0.85` (and fails or degrades with a fixed `settle_ms = 100`, proving the measurement matters; assert coverage with tuning is higher).
- `auto_exposure` with a camera that refuses `auto_exposure` returns `locked False`; with a fake camera whose brightness scales with exposure it returns an exposure whose white p99 is in 200–240.
- Scene with `gain = 0` → `CAMERA_NO_PROJECTION`.
