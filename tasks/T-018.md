## Goal

Define the output presets tuned for Raspberry Pi playback under Falcon Player (FPP), and an `Encoder` class that accepts raw frames and writes an H.264 + AAC MP4 through an ffmpeg pipe.

ffmpeg command built by `Encoder`:

```
ffmpeg -hide_banner -loglevel error -nostdin -y
  -f rawvideo -pix_fmt bgr24 -s {width}x{height} -r {fps} -i -
  [ -ss {audio_offset_ms/1000} -i {audio_path}      if audio_path is not None
  | -f lavfi -i anullsrc=r=48000:cl=stereo          otherwise (silent track) ]
  -map 0:v:0 -map 1:a:0 {video_args} {audio_args}
  -t {duration_ms/1000:.3f} -movflags +faststart {out_path}
```

Available: `facadekit.media.ffmpeg.ffmpeg_exe()`, `facadekit.errors.FkError`.

## Steps

1. Start ffmpeg with `stdin=PIPE`, `stdout=DEVNULL`, `stderr=` a temporary file (not a pipe: an unread stderr pipe can fill and deadlock).
2. `write`: validate `frame.shape == (height, width, 3)` and dtype `uint8` (`FkError("BAD_IMAGE_SIZE")`), then `stdin.write(frame.tobytes())`. A `BrokenPipeError` means ffmpeg died: read the stderr file and raise `FkError("FFMPEG_FAILED", tail)`.
3. `close`: close stdin, `wait()`, non-zero exit → `FkError("FFMPEG_FAILED", stderr tail)`. Delete the stderr temp file. Idempotent. Add `abort()` that kills ffmpeg and deletes the partial output file (used on cancel).
4. `-t` limits the audio to the video length; if the audio is shorter the rest is silent automatically only when the video stream is longer, which MP4 allows. Do not add `-shortest` (it would cut the video when the audio is shorter).
5. Level 4.0 allows at most 1920×1080 at 30 fps. In `Encoder.__init__`, if `preset.id` starts with `pi3-` and (`fps > 30` or `width*height > 1920*1088`), raise `FkError("BAD_REQUEST", "Preset pi3 supports at most 1080p30")`.

## Pitfalls

- Width and height must be even for `yuv420p`; `output_size` guarantees it, and `Encoder` should assert it.
- Windows: a path containing `'` or spaces is fine when passed as a list element.
- Never share one `Preset.video_args` list instance mutably; copy when building the command.

```
cd studio/backend && uv run pytest -q tests/test_render_encoder.py && uv run mypy src && uv run ruff check .
```

Tests (use `facadekit.media.probe.probe` to inspect results):

- `get_preset("nope")` → `FkError` `UNKNOWN_PRESET`; `PRESETS` has exactly the three ids.
- `output_size(pi3-1080p30, 1920, 1080) == (1920, 1080)`; `output_size(pi3-720p30, 1920, 1080) == (1280, 720)`; `output_size(preview-540p, 1280, 800) == (960, 600)`; `output_size(pi3-1080p30, 853, 480) == (852, 480)`.
- Encode 30 frames of 320×180 at 30 fps with `preview-540p` args and no audio, `duration_ms=1000`: output probes as video 320×180, `has_audio` true (silent track), duration 900–1100 ms.
- Same with `sample_audio` (3 s) as audio and `duration_ms=1000`: duration still 900–1100 ms.
- Encode with the real `pi3-1080p30` video args at 320×180: `ffmpeg -i` text of the output contains `High` and `yuv420p`.
- Writing a wrongly sized frame raises `BAD_IMAGE_SIZE`.
- `Encoder(..., fps=60, preset=pi3-1080p30)` raises `BAD_REQUEST`.
- `abort()` leaves no output file.
