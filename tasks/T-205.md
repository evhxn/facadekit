# T-205 – Scan memory: picture scale as context

- **Milestone:** v1.1 camera quality (docs/08 §3 "Scan memory")
- **Recommended model:** Haiku
- **Depends on:** T-202
- **Parallel with:** T-203, T-204

## Goal

When the user moves the camera closer (or switches to zoom) after a "too small" warning, the lessons learned at the old distance should count less. Add a coarse picture-scale class to the scan-memory context without changing behaviour for an empty log or for old log records.

## Steps

1. Add `scale_class`, the field and the weight factor. Thread `scale` through `posterior` and `choose` with default `None`.
2. In `ScanAdvisor.choose(camera_id, pre)`, pass `scale_class(pre.get("px_per_proj_px"))`. In `_record`, store `scale` the same way. `remembered_strategy` (Pi and phone scans) keeps passing no scale, because the scale is unknown before the recording.
3. The sibling-sharing rule (`SIBLING_SHARE`) uses the same weight, so it gets the factor automatically. Check that and say so in a code comment.
4. Update docs/07: one paragraph under "Context" and `scale` in the record description.
5. Re-run `uv run python -m facadekit.sim.learn_eval --n 18` and paste the before/after table into the PR. Regret must not regress: tuning ≤ 0.490, held-out ≤ 1.143.

## Pitfalls

- Empty log: `choose([], …, scale="coarse")` must return `standard`. Priors are untouched.
- Records written before this ticket have no `scale` key. `extra="ignore"` and the default `None` make them load, and they must count exactly as before (factor 1).
- `learn.py` may carry uncommitted edits from other work on this branch. Rebase; do not revert them.
