## Goal

Turn a video recorded with a phone's own camera app into a calibration. The laptop's projector window plays the self-clocked pattern sequence. The phone records it at any time, at any frame rate, in landscape or portrait. The backend finds the patterns from the flash marker, crops to the lit area, and builds the same calibration files as a webcam scan.

## Steps

1. **`segment_recording` parameter.** Default unchanged, so the Pi path and its tests are untouched. With `None`, `early = b` (the whole trace).
2. **`play_light_show`.**
   - Holds: `LEAD_IN` labels (black/white, projector-size gray), then `render_pattern(spec, f)` for every frame of `pattern_sequence(spec)`, then black for `TAIL_BLACK_S`. Every hold is `HOLD_FRAMES / VIDEO_FPS` s, the tail `TAIL_BLACK_S` s.
   - Show black first, then set `t0 = clock() + countdown_s`. Hold `k` is shown at the **absolute** deadline `t0 + k · hold_s`: `sleep(max(0, deadline − clock()))`, then `display.show(img)`.
   - Progress: "Starting in N s" once per second during the countdown, then "Light show k of n". Check cancel between holds; on cancel show black and raise `CANCELLED`.
3. **Video reading.** Write a private ffmpeg reader in `phone.py` (do not change `media/reader.py`, which is a fixed contract). It is a generator over `ffmpeg -nostdin -i path [-ss/-t] -an -vf "fps=30[,crop=w:h:x:y][,scale=W:H:flags=area]" -pix_fmt gray|bgr24 -f rawvideo -`.
   - Frame `i` has time `i / 30`.
   - Decoding failures, empty output or a `probe` error raise `PHONE_VIDEO_UNREADABLE`.
   - Reject videos shorter than `video_seconds(n)` or longer than `MAX_VIDEO_S`.
4. **`analyse_phone_video`.**
   - **Size.** `probe` gives the **displayed** size: check how `media/probe.py` handles rotation (`_ROTATION_RE`), and swap width and height yourself for ±90° if it does not. ffmpeg auto-rotates when decoding.
   - **Pass 1.** Decode at 160 px wide, gray. `windows = segment_recording(times, small, n, marker_search_s=None)`. An `FkError` from it is re-raised as `PHONE_VIDEO_NO_PATTERN`.
   - **Pass 2a.** Decode the BLACK window (pattern index 0) and the WHITE window (index 1) at full size, with `-ss`/`-t` slightly inside each window, and average each. `contrast = white − black`; `blob = lit_blob(contrast)`. If `not projection_found(blob)`, raise `CAMERA_NO_PROJECTION`.
   - **Crop.** `roi = suggest_roi(blob, W, H, max_area_fraction=1.0)` with `bin = 2` when `roi.w · roi.h > BIN2_ABOVE_PX`. Make w and h even before setting bin 2.
   - **Pass 2b.** Decode the whole video once with crop (+ scale for bin 2), gray. Add each frame inside window `k` to `sums[k]` (float32 `(N, h, w)`) and count it. `images = sums / counts`.
   - **White photo.** The middle frame of the WHITE window, decoded as `bgr24` with the same crop and scale.
   - **Motion check.** `a = images[white] − images[black]`; `b = max(images[last pattern], images[last inverse]) − images[black]`. Run `cv2.phaseCorrelate(a, b, window=cv2.createHanningWindow(...))`. If `hypot(dx, dy) · bin > MAX_SHIFT_PX`, raise `PHONE_MOVED`.
   - Return `CaptureSet(spec, frames, images, white_bgr, controls_applied={})` and the roi.
5. **`run_phone_calibration`.**
   - `spec = PatternSpec(*proj_size, skip_lsb=settings.skip_lsb)`. T-208 takes `proj_size` and the settings from the session file.
   - Analyse, then `settings = settings.model_copy(update={"roi": roi})`.
   - `run_calibration_from_capture(project_dir, capture, PHONE_CAMERA_ID, settings, strategy=..., advisor=...)` with `pre=None`, so the blob gate and scan-memory logging run as for Pi scans.
   - If it raises `SCAN_FAILED`, re-raise it with the message suffix " Did the phone move? Use a tripod or lean it on something steady." and keep the code, so scan memory logs it as usual.
6. **`make_phone_video`.**
   - Timeline: `preroll_s` of the projector off (`render_camera(None)`), then the holds of step 2 (no countdown needed: preroll plays that role), then `tail_s` of black.
   - The camera sees each hold `lag_frames` late. Render each hold once with `scene.render_camera`, then add per-frame noise by cycling 4 precomputed `normal(0, scene.noise_sigma)` fields.
   - From `shift_after_s` on, translate frames by `shift_px` (`np.roll` is fine).
   - Encode through an ffmpeg pipe: `-f rawvideo -pix_fmt bgr24 -s WxH -r fps -i - -c:v libx264 -preset ultrafast -crf 16 -pix_fmt yuv420p`.

## Pitfalls

- Phone videos are variable frame rate. The `fps=30` filter in **every** pass gives the same frame indexing in pass 1 and pass 2b. Do not use container timestamps directly.
- `-ss` before `-i` seeks to a keyframe and then decodes accurately (ffmpeg ≥ 2.1). Being ±1 frame off does not matter, because windows skip 25 % at both ends.
- Memory: never hold full-resolution frames of the whole video. Stream pass 2b and accumulate. 4K gray frames are 8.3 MB each.
- 10-bit HDR (iPhone HLG/Dolby Vision) decodes to washed-out but monotonic 8-bit. The inverse patterns make that harmless. Do not add tone mapping.
- Pattern labels from `LEAD_IN` are `"black"`/`"white"`. Patterns are indexed from `pattern_sequence`, where index 0 is BLACK and index 1 is WHITE.
- Do not log `PHONE_*` errors or `CAMERA_NO_PROJECTION` to scan memory (they happen before `run_calibration_from_capture`).

## Acceptance

```
cd studio/backend && uv run pytest -q tests/test_calib_phone.py tests/test_calib_selfclock.py && uv run mypy src && uv run ruff check .
```

Tests (scene `far_scene(0.9, cam_size=(1920, 1080), world_scale=2.0)`; true `s` ≈ 0.65; use `fps=15` in tests to keep them fast; total test time under 120 s):

- `segment_recording` with `marker_search_s=None` finds the windows in the T-113 synthetic trace with 25 s of black lead-in prepended. The default (15 s) still behaves as before on the existing tests.
- `play_light_show` with a fake clock and a `SimDisplay` that records `(clock(), image kind)`: show times are `t0 + k` exactly. With `show()` taking a random 0–80 ms (advance the fake clock), the k-th show still starts within 80 ms of `t0 + k`, with no accumulation over all holds.
- Phone video, `preroll_s=11.3`: calibration map corner error (`sim.e2e._map_corner_error` against `scene.h_p2c`) < 1.5 px, coverage ≥ 0.85, `camera_width/height == (1920, 1080)`, `settings.roi` set and smaller than the frame.
- `shift_after_s` at the middle of the patterns with `shift_px=(4, 0)` → `PHONE_MOVED`.
- A video cut 10 s before the end of the patterns → `PHONE_VIDEO_NO_PATTERN`.
- A text file renamed `.mp4` → `PHONE_VIDEO_UNREADABLE`.
- Rotation: if the bundled ffmpeg can write a rotation tag (`-display_rotation 90` as an input option, or `-metadata:s:v:0 rotate=90`), a rotated copy gives a corner error < 1.5 px. Otherwise `pytest.skip` with the reason. Spike S-10 covers real phone files.
