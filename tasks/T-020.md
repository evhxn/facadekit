# T-020 – Fake FPP server for tests

- **Milestone:** MVP
- **Recommended model:** Haiku
- **Depends on:** T-001
- **Parallel with:** T-008 … T-019, T-023

## Goal

Build a small FastAPI app that imitates the subset of Falcon Player's (FPP) REST API that FacadeKit uses, so the FPP client and publish flow can be tested without a Raspberry Pi.

## Background

FPP is the open-source show player that runs on the user's Raspberry Pi. FacadeKit uploads a video to it and creates a playlist through HTTP. Some details of FPP's API are assumptions to be confirmed on real hardware (spike S-1); if `spikes/S-1-fpp-contract.md` exists in the repo, read it and follow it where it disagrees with this ticket.

## Files to create

- `studio/backend/src/facadekit/fpp/fake.py`
- `studio/backend/tests/test_fpp_fake.py`
- Add to `studio/backend/tests/conftest.py`: fixture `fake_fpp` (see below)

## Interface

```python
def create_fake_fpp(state_dir: Path, *, version: str = "10.4") -> FastAPI
```

State on disk under `state_dir`: uploaded files in `state_dir/<DirName>/<name>`, playlists as `state_dir/playlists/<name>.json`. In-memory: `app.state.playing: str | None`, `app.state.requests: list[str]` (each handled request appended as `"METHOD /path"` for assertions).

Endpoints to implement (copied from docs/05-interfaces.md §7):

| Request | Behaviour |
|---|---|
| `GET /api/fppd/version` | `{"version": "10.4", "majorVersion": 10, "minorVersion": 4, "branch": "v10.4", "fppdAPI": "v1", "Status": "OK"}` (numbers derived from `version`) |
| `GET /api/system/info` | `{"HostName": "FakeFPP", "Platform": "Raspberry Pi", "Variant": "Pi 3 Model B", "Version": "10.4"}` |
| `GET /api/files/{DirName}` | `{"status": "ok", "files": [{"name": …, "sizeBytes": …}]}` for files in that dir (empty list if the dir does not exist) |
| `POST /api/file/{DirName}` (empty body) | 200 `{"status": "ok"}`; resets any partial upload for this dir |
| `PATCH /api/file/{DirName}` with headers `Upload-Name`, `Upload-Offset`, `Upload-Length` | Appends the raw body to `state_dir/<DirName>/.partial_<name>` after checking `Upload-Offset` equals the current partial size (else 409). When the size reaches `Upload-Length`, rename to the final name. 200 `{"status": "ok"}` |
| `GET /api/media/{name}/duration` | If `state_dir/videos/<name>` or `state_dir/music/<name>` exists: `{"<name>": {"duration": 60.0}}`; else 404 |
| `POST /api/playlist/{name}` | Stores the JSON body; 200 `{"status": "ok"}`; 400 if the body lacks `mainPlaylist` |
| `GET /api/playlist/{name}` | Stored JSON or 404 |
| `GET /api/playlists` | List of names |
| `POST /api/playlist/{name}/start` | 404 if unknown; else sets `playing = name`; 200 |
| `POST /api/playlists/stop` | `playing = None`; 200 |
| `GET /api/fppd/status` | `{"status_name": "playing" or "idle", "current_playlist": {"playlist": playing or ""}, "seconds_played": "0"}` |

Fixture for `conftest.py`:

```python
@pytest.fixture
def fake_fpp(tmp_path):
    """Runs the fake FPP on 127.0.0.1:<free port> in a background thread.
    Yields an object with .host ("127.0.0.1:<port>"), .state_dir (Path), .app (FastAPI)."""
```

Run it with `uvicorn.Server(uvicorn.Config(app, host="127.0.0.1", port=<free port>, log_level="warning"))` in a daemon thread; wait until `server.started` is true; on teardown set `server.should_exit = True` and join. Find a free port by binding a socket to port 0.

## Pitfalls

- Reject names containing `/`, `\` or `..` in `{DirName}`, `{name}` and `Upload-Name` with 400 (keeps the fake from writing outside `state_dir`).
- Read the PATCH body with `await request.body()`; do not declare it as a form.
- Keep the module free of imports from other `facadekit` packages except `errors` (it must work standalone).

## Acceptance

```
cd studio/backend && uv run pytest -q tests/test_fpp_fake.py && uv run mypy src && uv run ruff check .
```

Tests (use `httpx` against the `fake_fpp` fixture): version returns `majorVersion == 10`; `create_fake_fpp(version="9.2")` returns 9; two-chunk upload to `videos` produces a file with the concatenated bytes and it is listed by `GET /api/files/videos`; a wrong `Upload-Offset` returns 409; media duration 200 after upload and 404 before; playlist save → get round trip; start sets status `playing` with the playlist name; stop returns to `idle`; start of an unknown playlist is 404; `..` in a name is 400.

## Out of scope

Any other FPP endpoint, authentication, MultiSync, realism of status fields.
