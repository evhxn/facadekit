## Goal

Support surfaces that are not flat (a bowed garage door, a stepped wall) by letting each surface carry a grid of control-point offsets that bends the content after the perspective mapping. This ticket implements the math and the renderer; T-111 adds the editor and preview.

## Definition (normative)

For a point with surface-unit coordinates `(u, v) ∈ [0,1]²`:

```
base(u, v)   = apply_h(quad_homography(1, 1, surface.quad), (u, v))          # projector px
offset(u, v) = bilinear interpolation of mesh.offsets over the grid, where control point (i, j)
               (row i in 0..rows, column j in 0..cols) sits at (u, v) = (j / cols, i / rows)
final(u, v)  = base(u, v) + offset(u, v)
```

A mesh with all-zero offsets is identical to no mesh.

## Steps

1. `mesh_inverse_map` by forward rasterisation: sample the unit square on a fine grid of `(rows·subdiv + 1) × (cols·subdiv + 1)` points, compute `final(u, v)` for each (vectorised), then for every fine cell rasterise its two triangles into the output with barycentric interpolation of `(u, v)`. Efficient approach with OpenCV: render two float images `U` and `V` over the unit square (e.g. 512×512 gradients) and warp them cell by cell with `cv2.warpAffine` per triangle into the output using a triangle mask (`cv2.fillConvexPoly`), or implement the barycentric fill with NumPy per triangle bounding box. With `subdiv=8` and a 16×16 mesh this is at most 32 768 triangles: acceptable because it is computed once per surface, not per frame. Initialise both maps to −1.
2. In `Compositor`, for a surface with a non-null mesh that has any non-zero offset:
   - Precompute `(map_u, map_v)` once at the output scale (scale quad points and offsets by `scale`).
   - Per clip, convert to source pixel maps: with `(src_rect, dst_unit_rect) = fit_rects(...)`, a pixel with unit coordinate `(u, v)` inside `dst_unit_rect` samples the source at `x = x0 + (u − u0) / (u1 − u0) · (x1 − x0)` (same for y); outside `dst_unit_rect` or where the map is −1 the alpha is 0. Sample with `cv2.remap(src, map_x, map_y, cv2.INTER_LINEAR, borderMode=cv2.BORDER_CONSTANT)`.
   - The surface mask: if `surface.mask` is null, the visible area is where `map_u >= 0` (the warped quad), softened by `feather_px` (Gaussian blur of that coverage image, sigma `feather_px / 2`); if a mask polygon exists it is used unchanged (it is already in projector space).
3. Surfaces without a mesh, or with an all-zero mesh, must take the existing homography path (byte-identical output to before; assert this in a test).
4. Validation: `len(offsets) == (cols+1)*(rows+1)` is already enforced by the model.

## Pitfalls

- Folded meshes (control points crossing) produce overlapping triangles; last-drawn wins. That is acceptable; do not try to detect folds here.
- Keep triangle winding irrelevant: use masks, not culling.
- Cracks between triangles: rasterise with a mask that includes the triangle's edges (fill then also draw the outline 1 px) so no −1 pixels remain inside the surface.

cd studio/backend && uv run pytest -q tests/test_geom_mesh.py tests/test_render_compositor.py && uv run mypy src && uv run ruff check .

Tests: zero-offset 2×2 mesh on a trapezoid: `mesh_inverse_map` agrees with the inverse homography within 0.01 in `u, v` at 200 random interior pixels and is −1 outside; `mesh_control_points` of a zero mesh on a unit-aligned 100×100 square with `cols=rows=2` gives the 3×3 lattice at 0, 50, 100; moving the centre control point of a 2×2 mesh by `(+20, 0)`: the output pixel at `base(0.5, 0.5) + (20, 0)` maps to `(u, v) ≈ (0.5, 0.5)` (±0.01) and corners are unchanged; compositor: a vertical-stripe image (left half red, right half blue) on a surface whose centre column is shifted +20 px shows the red/blue boundary about 20 px to the right at mid-height (±2 px) and unmoved at the top edge; all-zero mesh output is identical to `mesh=None`.
