# T-029 – Web API client, types, events and project store

- **Milestone:** MVP
- **Recommended model:** Sonnet
- **Depends on:** T-002 (and the route table below; the backend does not need to be running for the tests)
- **Parallel with:** T-024 … T-028, T-030

## Goal

Give the web UI a typed layer over the backend: TypeScript types mirroring the JSON schemas, a fetch client, an events WebSocket client, user-facing error messages, and a Zustand store that loads, edits and auto-saves the current project.

## Files to create

Under `studio/web/src/`: `api/types.ts`, `api/client.ts`, `api/events.ts`, `api/errors.ts`, `state/projectStore.ts`, and tests `api/client.test.ts`, `state/projectStore.test.ts`.

## Specification

- `api/client.ts`: `class ApiError extends Error { code: string; status: number }`. One internal `request<T>(method, path, body?)` that sets JSON headers, parses the error body, and throws `ApiError` (code `NETWORK` when `fetch` rejects). `uploadAsset` uses `XMLHttpRequest` for upload progress.
- `api/events.ts`: `connectEvents(onMessage): () => void` opens `ws(s)://<location.host>/ws/events`, reconnects with backoff 0.5 s → 5 s, returns a disposer. Also `waitForJob(jobId, onUpdate?): Promise<Job>` that resolves when the job reaches a final state, using events and falling back to polling `getJob` every 1 s (covers a missed event).
- `api/errors.ts`: `userMessage(code: string, fallback: string): string` with friendly text for at least: `RESOLUTION_MISMATCH`, `CAMERA_NO_PROJECTION`, `TOO_BRIGHT`, `SCAN_FAILED`, `PROJECTOR_NOT_CONNECTED`, `PROJECTOR_TIMEOUT`, `CAMERA_OPEN_FAILED`, `FPP_UNREACHABLE`, `FPP_TOO_OLD`, `FPP_UPLOAD_FAILED`, `UNSUPPORTED_MEDIA`, `ASSET_IN_USE`, `REVISION_CONFLICT`, `NETWORK`. Wording for the calibration ones:
  - `TOO_BRIGHT`: "It is too bright to scan. Try again after sunset or turn off nearby lights."
  - `CAMERA_NO_PROJECTION`: "The camera cannot see the projection. Move the camera so the whole white rectangle is inside the picture."
  - `RESOLUTION_MISMATCH`: "Your computer is not sending the projector its native resolution. Set the projector display to the project's resolution and 100 % scaling."
  - `SCAN_FAILED`: "The scan did not work. Try again, move the camera closer to the projector, or use manual mode."
- `state/projectStore.ts` (Zustand): state `{ project: Project | null, dirty: boolean, saving: boolean, error: string | null }`; actions `load(id)`, `update(mutator: (draft: Project) => void)`, `saveNow(): Promise<void>`, `replace(project)` (used when the server returns a newer project, e.g. after an upload). `update` deep-clones with `structuredClone`, applies the mutator, sets `dirty`, and schedules a save 500 ms later (debounced). Saves are serialised: if a save is in flight, the next waits. After a successful save, take only `revision` from the response if more edits happened meanwhile. On `REVISION_CONFLICT`: reload from the server, set `error` to the friendly message.
- `newId(prefix)` helper in `api/types.ts`: `prefix + "_" + 8 hex chars` from `crypto.getRandomValues`.

## Acceptance

```
cd studio/web && pnpm lint && pnpm typecheck && pnpm test
```

Tests (mock `fetch` with `vi.fn`, fake timers for debounce): `getProject` parses a project; a 409 response throws `ApiError` with `code === "REVISION_CONFLICT"` and `status === 409`; a rejected fetch throws code `NETWORK`; `putProject` sends `PUT` to `/api/v1/projects/<id>` with a JSON body; store `update` twice within 500 ms triggers exactly one PUT containing both edits; after save `dirty` is false and `revision` incremented; a conflict response triggers a reload and sets `error`; `userMessage("TOO_BRIGHT", "x")` returns the specified sentence and an unknown code returns the fallback; `newId("srf")` matches `/^srf_[0-9a-f]{8}$/`.
