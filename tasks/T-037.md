# T-037 – Preview / render parity test (browser)

- **Milestone:** MVP
- **Recommended model:** Sonnet
- **Depends on:** T-028, T-033, T-034
- **Parallel with:** T-038

## Goal

Automatically check that the WebGL preview in the browser and the authoritative Python renderer produce nearly the same picture for a set of fixed scenes, so users can trust what they see while editing.

## Background

FacadeKit has two compositors on purpose: a fast approximate one in WebGL (`studio/web/src/gl/compositor.ts`) and an exact one in Python (`facadekit/render/compositor.py`) that produces the final video. They implement the same rules (per-surface homography, fit modes, opacity, fades, blend modes). Feathered edges are only approximated in WebGL, so the comparison excludes feather.

## Files to create or modify

- `studio/web/playwright.config.ts`, `studio/web/e2e/parity.spec.ts`, `studio/web/e2e/scenes.ts`
- `studio/web/src/pages/DevParityPage.tsx` and a route `/dev/parity` (only registered when `import.meta.env.DEV` or the URL has `?dev=1`)
- `studio/web/package.json`: add dev dependencies `@playwright/test`, `pngjs`, `jpeg-js`; script `"e2e": "playwright test"`
- `.github/workflows/ci.yml`: add an ubuntu job `parity` that builds the web UI, starts the backend, and runs `pnpm e2e`

## Interfaces available

Backend HTTP (prefix `/api/v1`): `POST /projects` `{name, projector}` → `Project`; `POST /projects/{pid}/assets` (multipart `file`) → `{asset, project}`; `PUT /projects/{pid}` (full `Project` with current `revision`) → `Project`; `GET /projects/{pid}/frame?t_ms=<int>&scale=1` → JPEG of the exact frame.

Web: `new PreviewCompositor(canvas, {assetUrl})`, `.setProject(project)`, `.render(tMs, playing)`; `assetUrl(pid, aid)`; `getProject(id)`.

Start the backend for tests with: `uv run facadekit serve --no-browser --port 8137 --data-dir <temp dir>` from `studio/backend` (it serves the built UI from `webdist/`, so run `pnpm build` first).

## Specification

1. `DevParityPage` reads `?project=<id>&t=<ms>`, loads the project, creates a canvas with backing size exactly the projector size (CSS size the same, no scaling), creates a `PreviewCompositor` with `preserveDrawingBuffer: true` (add an optional constructor option `preserveDrawingBuffer?: boolean` to `PreviewCompositor` if it does not exist), renders time `t` with `playing=false`, waits until all image sources are loaded (expose a promise `compositor.ready()` resolving when every source for the active clips has a texture; add it if missing), renders again, then sets `window.__parityReady = true`.
2. `scenes.ts` defines scenes for a 480×270 projector using only **image** assets (PNG files generated in the test with `pngjs`: solid colours, a two-colour split image, and a 4×4 checkerboard of 60 px squares) so results do not depend on video decoding:
   - `stretch-trapezoid`: checkerboard on a strongly perspective quad `[[120,40],[400,70],[440,250],[60,220]]`, `fit: "stretch"`.
   - `fill-square`: split image on an axis-aligned square surface with `aspect: 1`, `fit: "fill"`.
   - `fit-wide`: square image on a surface with `aspect: 2`, `fit: "fit"`.
   - `opacity-add`: two overlapping surfaces on two tracks, top clip `blend: "add"`, `opacity: 0.6`.
   - `screen`: same with `blend: "screen"`.
   - `fade`: one clip with `fade_in_ms: 1000`, evaluated at `t = 500`.
   - `canvas`: an image on `surface_id: "canvas"` with `fit: "fit"`.
3. For each scene the spec: creates the project through the API, uploads assets, PUTs the project, opens `/dev/parity?project=<id>&t=<ms>&dev=1`, waits for `__parityReady`, reads the canvas pixels with `page.evaluate(() => canvas.toDataURL("image/png"))`, fetches the backend frame JPEG, decodes both (`pngjs`, `jpeg-js`), and compares.
4. Comparison metric: convert both to RGB; ignore pixels within 3 px of any surface-quad edge (anti-aliasing differs; compute an edge mask by rasterising the quad outlines with a 7 px wide stroke in a helper); over the remaining pixels require mean absolute difference per channel < 4 and fewer than 0.5 % of pixels differing by more than 24 in any channel.
5. On failure, write `preview.png`, `backend.png` and `diff.png` into `test-results/<scene>/` for inspection.
6. Playwright config: Chromium only; launch args `--use-gl=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist` so WebGL2 works headless in CI; `baseURL http://127.0.0.1:8137`; `webServer` entry that runs the backend command above (with `reuseExistingServer: true`).

## Pitfalls

- The checkerboard on a perspective quad is the test that catches non-perspective-correct texturing: an affine-per-triangle bug produces a visible kink along the diagonal and fails the metric.
- JPEG from the backend adds small errors; the thresholds above allow for quality 85.
- If parity fails because the **backend** or the **WebGL compositor** has a real bug, do not loosen thresholds. Write the scene name and the diff image path in `tasks/BLOCKERS.md`.
- Colour space: the canvas must be created without colour management surprises; use `{ alpha: false, premultipliedAlpha: true, colorSpace: "srgb" }` context attributes.
