# T-208 – Phone scan flow: routes, wizard panel, phone page

- **Milestone:** v1.1 phone camera (docs/08 §4, §5)
- **Recommended model:** Sonnet
- **Depends on:** T-117, T-206, T-207
- **Parallel with:** none

## Goal

Let the user scan with their phone:

- Press **Start light show** on the laptop or on the phone.
- Record with the phone's camera app.
- Send the video from the laptop or straight from the phone over the home Wi-Fi.
- Get the same scan result screen as a webcam scan.

## Files to create or modify

- Backend: modify `api/routes_calibration.py` (two routes), `api/remote_auth.py` (allowlist) ⚑; create `tests/test_api_phone_scan.py`
- Web:
  - create `pages/setup/PhoneScanPanel.tsx` (+ test) and `pages/PhonePage.tsx` (+ test, route `/phone/:projectId`);
  - modify `pages/setup/StepScan.tsx` (panel, replaces T-206's placeholder), `api/client.ts`, `api/types.ts`, `api/errors.ts` (three messages), `App` router.

## Interfaces (new ⚑)

```
POST /api/v1/projects/{pid}/phone-scans          body {"countdown_s": int = 15 (5..60), "learn": bool = true}
     -> 202 {"session_id": "phs_xxxxxxxx", "job_id": str}
     job kind "calibration": play_light_show(display, spec, countdown_s); result {"session_id"}
POST /api/v1/projects/{pid}/phone-scans/{sid}/video   multipart field "file"
     -> 202 {"job_id"}; job kind "calibration": run_phone_calibration(...); result {"calibration_id"}
Remote allowlist additions (paired phone): POST /api/v1/projects/[^/]+/phone-scans,
     POST /api/v1/projects/[^/]+/phone-scans/phs_[0-9a-f]{8}/video, GET /api/v1/jobs/[^/]+
```

Session file `<project>/calibration/.phone/<sid>.json`:

```
{"id", "created_at", "proj_w", "proj_h", "skip_lsb", "min_conf", "strategy": str | null, "learn": bool}
```

Sessions older than 24 h → `NOT_FOUND` "This light show has expired. Start it again."

## Specification

Backend:

1. **Start.**
   - Strategy: when learning is enabled (`learn` true, `FACADEKIT_LEARN` not 0), `advisor.remembered_strategy("phone") or STRATEGIES[0]`; otherwise `CalibSettings()` defaults with strategy null.
   - Write the session file, then submit the playback job using the projector display exactly as the laptop scan job does (`PROJECTOR_NOT_CONNECTED` if none).
2. **Video.**
   - Check the session exists.
   - Reject `Content-Length` > 4 GB, or free disk (`shutil.disk_usage`) < size + 1 GB, with `BAD_REQUEST` and a plain message.
   - Stream the upload to `.phone/<sid>.upload` in 1 MB chunks.
   - Submit the analysis job: `run_phone_calibration(..., settings=CalibSettings(skip_lsb, min_conf), proj_size, strategy, advisor if session.learn)`.
   - On success, attach the calibration like a scan (`_attach_calibration`, project event).
   - In `finally`, delete the upload unless `FACADEKIT_KEEP_PHONE_VIDEO=1`, and delete the session file after success.
3. **Allowlist.** Add the three entries to `_REMOTE_ROUTES`. No other change to T-117 rules. The upload route must still reject non-paired LAN clients (existing middleware).

Web:

4. **PhoneScanPanel** (StepScan; opened by **Use my phone instead** from T-206 via `?phone=1`, or by a "Scan with your phone" link under **Start scan**):
   - The four numbered instructions and the privacy note from docs/08 §5, verbatim (put them in `cameraCopy.ts`).
   - **Start light show.** Shows the countdown from job progress messages, then "Light show running… keep recording", then "Done. Stop recording and send the video."
   - **Choose video…** is `<input type="file" accept="video/*">`. Upload with `XMLHttpRequest` (progress bar from `upload.onprogress`), then `waitForJob`, then the same result screen as a webcam scan. Reuse StepScan's done view: extract it into a component if needed.
   - "Send from your phone instead": if `remote/info.enabled`, show the QR code (`components/qr.ts`) for `<url>/phone/<project id>` and the pairing code. Otherwise show the T-117 restart instruction.
5. **PhonePage** (`/phone/:projectId`, portrait, large buttons):
   - Pair with the code (reuse the RemotePage pairing component; extract it if it is inline).
   - **Start light show in 20 s** calls `POST phone-scans` with `countdown_s: 20` and stores `session_id` in `sessionStorage`, then says "Now switch to your camera app and start recording."
   - **Send video**: file input plus XHR upload with progress, then "Done. Look at your computer for the result." If there is no session in `sessionStorage`: "Start the light show first."
6. Error messages (`api/errors.ts`):
   - `PHONE_MOVED`, `PHONE_VIDEO_NO_PATTERN`, `PHONE_VIDEO_UNREADABLE`: text from docs/08 §4.
   - Phone `SCAN_FAILED` already carries the "Did the phone move?" suffix from the backend.

## Pitfalls

- `getUserMedia` is **not** used anywhere. The page works over plain `http://192.168.x.x`.
- Do not add the `capture` attribute to the file input: it would open a bare in-browser recorder instead of letting the user pick the native camera app's recording.
- `fetch` has no upload progress; use XHR. Send the `fk_remote` cookie: same origin, so it is automatic.
- The playback job holds the projector for about 65 s. A second start while one runs → 409 with "A light show is already running."
- Do not widen the allowlist beyond the three entries (no deletes, no renders, no other uploads).

## Acceptance

```
cd studio/backend && uv run pytest -q tests/test_api_phone_scan.py tests/test_api_remote.py && uv run mypy src && uv run ruff check .
cd studio/web && pnpm lint && pnpm typecheck && pnpm test
```

Backend tests (sim app; monkeypatch `phone.play_light_show` to a no-op, and generate the video with `make_phone_video` at fps 15, or reuse a cached file from T-207's test helper):

- start → session file exists, job succeeds;
- upload → job succeeds, `project.calibration_id` set, upload file deleted;
- upload to an unknown or expired session → 404;
- oversized `Content-Length` → 400;
- paired LAN client: start and upload allowed, `GET /jobs/{id}` allowed, `POST /projects/{pid}/renders` still 403;
- unpaired LAN client: upload → 403;
- a failed analysis (`PHONE_VIDEO_UNREADABLE`) also deletes the upload.

Web tests:

- the panel shows the countdown text from a mocked job progress message;
- choosing a file calls the upload with the session id and shows progress;
- PhonePage shows "Start the light show first" without a session, and after start shows the camera-app instruction;
- the error messages map correctly.

## Out of scope

Phone with Pi playback, resumable uploads, HTTPS, browser camera streaming, keeping uploaded videos.
