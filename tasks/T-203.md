# T-203 – Camera crop in the scan pipeline

- **Milestone:** v1.1 camera quality (docs/08 §2)
- **Recommended model:** Sonnet
- **Depends on:** T-202
- **Parallel with:** T-205

## Goal

Let a scan use only a rectangle of the camera picture (the lit area). The crop is applied at capture time; all stored results stay in full-frame camera coordinates, so nothing downstream changes and old calibrations stay valid.

## Files to create or modify

- Modify `studio/backend/src/facadekit/models/calibration.py` (`CameraRoi`, `CalibSettings.roi`) ⚑
- Create `studio/backend/src/facadekit/devices/cropped.py` (`CroppedCamera`), `calib/roi.py`, `tests/test_calib_roi.py`
- Modify `calib/pipeline.py` (`run_calibration`, `_decode_capture`)

## Steps

1. Models and validators, `CroppedCamera`, `roi.py`.
2. `run_calibration`: when `settings.roi` is set, wrap the camera once, `camera = CroppedCamera(camera, settings.roi)`, before `camera.open()`. Latency tuning, exposure search, precheck and capture then run on the crop unchanged.
3. `_decode_capture`: decode and `build_maps` in crop coordinates as today; `make_proj_view(capture.white_bgr, maps)` **before** conversion; then `maps = maps_to_full(maps, roi)` and write `p2c.npy` and `h_c2p` from the converted maps.
   - `camera_width/height` = `roi.frame_width/height`.
   - Precheck's `lit_fraction` is relative to the crop. Store `lit_px / (frame_width · frame_height)` instead.
   - Add warning `CROP_TOO_TIGHT` ⚑ when `crop_too_tight` on the precheck blob (pass the flag through `pre` as `crop_tight: 1.0/0.0`).
   - `px_per_proj_px_from_h` uses the full-frame `h_c2p`; the `bin` is accounted for by the affine.
4. `run_calibration_from_capture` gets the roi from `settings.roi` as well (used by T-207). If the capture's image size is not `(roi.h // bin, roi.w // bin)`, raise `INTERNAL`.
5. Without a roi, every code path must be byte-identical to before.

## Pitfalls

- Integers only. Never store a float crop. The half-pixel convention needs no correction precisely because offsets and the bin factor are integers. Do not add or subtract 0.5 anywhere in this ticket.
- `make_proj_view` must receive the **cropped** white photo together with **crop-coordinate** maps. Convert after it, not before.
- `h_c2p @ inv(A)`, not `inv(A) @ h_c2p`: full-frame point → crop point (`inv(A)`) → projector (`h_c2p`).
- float32 `p2c` at 4K: tests use `atol=1e-3`.
- `SimCamera` draws noise from its own RNG per `read()`. Cropping after reading keeps the sequence identical, so the exactness test below is valid.

## Acceptance

```
cd studio/backend && uv run pytest -q tests/test_calib_roi.py tests/test_calib_capture.py tests/test_calib_maps.py tests/test_sim_e2e.py && uv run mypy src && uv run ruff check .
```

Tests:

- `CameraRoi` validators reject negative, too small, out-of-frame and odd-with-bin-2 crops.
- **Exactness:** run `run_capture` on `default_scene()` twice, full and with `CroppedCamera(roi=(100, 60, 900, 520))`, using fixed settings (`settle_ms=0` path off, `average_frames=1`, `discard_frames=0`) and fresh `SimCamera`s with the same seed. Cropped images `np.array_equal` the full images sliced. Do it with exposure tuning stubbed out if it reads a different number of frames for the crop; document what you did.
- `maps_to_full` on a synthetic `ProjectorMaps`: `p2c` shifts by exactly (x, y) (bin 1) and maps `2·v + (x, y)` (bin 2), `atol=1e-3`. `apply_h(h_full, [[u + x, v + y]]) == apply_h(h_crop, [[u, v]])` within 1e-6.
- **Equivalence on the default scene:** a scan with `suggest_roi(precheck blob, max_area_fraction=1.0)` and a scan without a crop have median |Δp2c| over measured pixels ≤ 0.25 px, and both sim-e2e-style map corner errors (`sim.e2e._map_corner_error` against `scene.h_p2c`) are < 1.5 px.
- `scene_phone()` with the suggested crop: map corner error < 1.5 px.
- `scene_far_marginal()` with the suggested crop and `skip_lsb=3`: coverage ≥ 0.85 and map corner error < 3.0 px. If this fails, stop and report the numbers; do not tune thresholds here.
- `suggest_roi` returns None for the default scene when the box is over 60 % of the frame (assert either way and print the area fraction).
- The resolution-mismatch crop raises `BAD_REQUEST`.
