## Goal

Given a project and a time, produce the exact output frame: every active clip warped onto its surface, masked, faded and blended. This defines what the projector will show; the browser preview imitates it.

## Compositing rules (copied from docs/02-architecture.md §6.2)

For output time `t_ms`:

1. Start with an opaque black frame.
2. For each track from index 0 upward, for each clip with `start_ms ≤ t_ms < start_ms + duration_ms`:
   1. Source time `s = in_offset_ms + (t_ms − start_ms)`. If `loop` and the asset has a duration, `s = s mod asset.duration_ms`. If not looping and `s ≥ asset.duration_ms`, hold the last frame. Images ignore `s`.
   2. `H, src_rect = clip_homography(src_w, src_h, surface, clip.fit)`.
   3. Warp the source with `H` to the output size, bilinear.
   4. Alpha `a = source alpha (1 if none) × surface mask × clip.opacity × fade(t)`. The mask is the surface's `mask` polygon, or its quad if `mask` is null, rasterised with feather. `fade = min(1, (t − start)/fade_in_ms) × min(1, (start + duration − t)/fade_out_ms)` with a zero-length fade counting as 1.
   5. Blend: `normal`: `dst = src·a + dst·(1−a)`; `add`: `dst = min(1, dst + src·a)`; `screen`: `dst = 1 − (1−dst)(1−src·a)`.
3. Blending is done directly on gamma-encoded values (no linearisation).

Clips with a `generator` (v1 feature) are skipped silently in this ticket.

## Steps

1. In `__init__`: scale every surface (quad points, mask points, feather) by `scale`; precompute and cache per surface the mask image (`float32`). Build a dict of surfaces including `"canvas"`. Create `ClipSource` objects lazily per asset id with `fps=project.projector.fps` and `max_size=self.size`. **One `ClipSource` per clip, not per asset** (two clips may read the same file at different positions).
2. The source frame from `ClipSource` has `source.size`, which may be smaller than the asset's nominal size. Compute the homography with the *decode* size: `clip_homography(source.size[0], source.size[1], surface, fit)`.
3. Crop to `src_rect` implicitly: the homography maps the whole source plane, so pixels outside `src_rect` land outside the surface quad for `fill`. They must still be removed: build the alpha by warping a `uint8` rectangle image that is 255 inside `src_rect` (and multiplied by the source alpha channel if present) with the same `H`, then multiply by the surface mask. This handles `fit` letterbox bars (transparent) and `fill` cropping uniformly.
4. Warp with `cv2.warpPerspective(src, H, (W_out, H_out), flags=cv2.INTER_LINEAR, borderMode=cv2.BORDER_CONSTANT, borderValue=0)`.
5. Speed: restrict blending to the bounding box of the surface mask (compute once per surface via `cv2.boundingRect` of `mask > 0`). Work in `float32` 0..1 inside the box, write back as `uint8` at the end of the frame.
6. `close()` closes all sources. Support use as a context manager.

## Pitfalls

- When `src_rect` covers the whole source, skip warping the rectangle image and use the quad mask directly only if the source has no alpha; otherwise edges get slightly different anti-aliasing. Simpler and always correct: always warp the rectangle alpha. Do that.
- `duration_ms` is `None` for images; never take a modulo with `None`.
- A clip whose asset file is missing on disk: raise `FkError("NOT_FOUND", "Media file missing: <original_name>")` from `frame()`.
- Strong downscales (4K source onto a small window) alias with bilinear warping; `ClipSource(max_size=self.size)` already limits this. Do not add mip-mapping.

## Acceptance

```
cd studio/backend && uv run pytest -q tests/test_render_compositor.py && uv run mypy src && uv run ruff check .
```

Tests build small projects in `tmp_path` (projector 320×180, 30 fps) with solid-colour PNG assets written by `cv2.imwrite` and the `sample_video` fixture:

- One red image clip on a centred square surface `((100,40),(220,40),(220,140),(100,140))`, `fit="stretch"`: pixel `(160, 90)` is red `(0,0,255)` BGR; pixel `(20, 20)` is black.
- `opacity=0.5` → centre pixel ≈ `(0,0,128)` (±2).
- `fade_in_ms=1000`: at `t=500` centre ≈ `(0,0,128)` (±6); at `t=1000` full red.
- Two tracks, green over red, upper `blend="add"` → centre `(0,255,255)`; upper `blend="normal"` → `(0,255,0)`.
- `screen` of two 50 % gray images → ≈ 191 (±3).
- Clip outside its time range contributes nothing.
- `fit="fit"` of a 100×100 image on a surface with `aspect=2.0` and an axis-aligned 200×100 quad: the centre is coloured, a point 10 px inside the left edge of the quad is black (letterbox).
- `fit="fill"` of a 200×100 image whose left half is blue and right half is white, on a square surface with `aspect=1.0`: left quarter of the surface is blue, right quarter white (centre crop keeps the middle 100×100).
- Perspective: on a trapezoid surface the pixel at the quad's centroid is coloured and a pixel just outside each edge is black.
- `surface_id="canvas"` covers the full frame.
- `scale=0.5` returns a 160×90 frame whose centre pixel matches the full-scale frame's centre colour.
- Video clip with `loop=True`, `duration_ms=5000` on the 2 s sample: `frame(500)` and `frame(2500)` are nearly identical (mean abs diff < 8).
- PNG with a transparent left half: left half of the surface shows the track below.
