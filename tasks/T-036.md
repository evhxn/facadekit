## Goal

## Interfaces (copied from docs/05-interfaces.md)

CLI (exit codes: 0 success, 1 `FkError` printed as `CODE: message` on stderr, 2 usage error):

```
facadekit calibrate PROJECT_DIR (--sim | --manual)                 # real hardware calibration needs the UI
facadekit render   PROJECT_DIR [--preset pi3-1080p30] [--out PATH] [--no-audio] [--alignment-check]
facadekit publish  PROJECT_DIR --host HOST [--render PATH] [--playlist NAME] [--start]
facadekit doctor                                                    # prints versions, ffmpeg path, cameras found, data dir
facadekit sim e2e  [--workdir PATH]                                 # full simulated run; prints max corner error in px
```

`PROJECT_DIR` is a path to a `.fkproj` folder. `render` default output: `PROJECT_DIR/renders/<new render id>.mp4`. `publish` default `--render`: the newest `*.mp4` in `PROJECT_DIR/renders/`; default media name `fk_<project id>.mp4`; default playlist `FacadeKit - <project name>`.

## The end-to-end procedure

1. Create `workdir/e2e.fkproj` (folders `media`, `calibration`, `renders`) with a default 1920×1080@30 project.
2. `scene = default_scene()`; scan with `SimDisplay`/`SimCamera`, `sleep=lambda s: None`, `CalibSettings(discard_frames=0, average_frames=1)`; set `project.calibration_id`.
3. **Find the garage door on the projector view automatically** (stands in for the user drawing it): load `proj_view.png`; the simulated door is the largest light-gray region. Threshold: pixels where all three channels are > 110 under white projection and the channel spread `max − min < 40`; morphological open 5×5; largest connected component; `cv2.approxPolyDP` on its contour with epsilon = 2 % of the perimeter, increasing by 1 % until exactly 4 points (give up with `FkError("INTERNAL")` after 10 tries); order the corners TL, TR, BR, BL (sort by y then x within each pair). Then refine to sub-pixel accuracy: for each of the four sides take the contour points lying between its two approximate corners, drop the 15 % nearest each corner, fit a line with `cv2.fitLine(..., cv2.DIST_L2, 0, 0.01, 0.01)`, and replace each corner by the intersection of its two adjacent fitted lines.
4. Create a surface with that quad and `aspect = estimate_aspect(quad)`.
5. Create a test image asset `media/<id>.png`, 640×360, solid green `(0, 255, 0)` BGR with a 20 px magenta `(255, 0, 255)` border, add it as an asset (use `probe`-equivalent fields directly), and one clip: that asset on the surface, `fit="stretch"`, 0–2000 ms; `timeline.duration_ms = 2000`. Save.
6. `render_project(project_dir, "pi3-1080p30", renders/<id>.mp4)`.
7. **Verification**: `frame = Compositor(project, project_dir).frame(1000)`. Compare the detected quad with the ground truth `scene.feature_quad_proj("garage_door")`: `max_corner_error_px` = the largest distance between corresponding corners. Additionally project the frame through the simulator (`scene.render_camera(frame, rng)`) and assert that the camera pixel at the door centre (`apply(scene.h_p2c, centroid of the truth quad)`) is green-dominant (G > R + 40 and G > B + 40), and that the camera pixel at the wall point 60 world px left of the door's left edge is not green-dominant.
8. If `publish_host` is given: `publish_render(publish_host, render_path, media_name="fk_e2e.mp4", playlist_name="FacadeKit - E2E", start=True)`.
9. Log each stage; return the result.

`facadekit sim e2e` runs this in `--workdir` (default: a new temp dir), prints `max corner error: X.XX px`, `coverage: NN %`, the render path, and exits 1 with code `INTERNAL` if the error is ≥ 3.0 px or the colour checks fail.

## Other commands

- `calibrate --sim`: steps 1–2 on an existing project folder (the project's projector size must be 1920×1080, else `RESOLUTION_MISMATCH`), saves `calibration_id`, prints the calibration id and coverage. `--manual`: `create_manual_calibration`.
- `render`: prints a one-line progress (`\rRendering 42%`) when stderr is a TTY; prints the output path on success.
- `publish`: prints progress messages; prints the playlist name on success.
- `doctor`: prints `facadekit <version>`, Python version, OpenCV version, `ffmpeg: <path>` plus the first line of `ffmpeg -version`, `data dir: <path>`, and `cameras: <n>` followed by each camera. Never fails because no camera exists. `--no-cameras` skips camera probing (used in tests).

## Pitfalls

- The corner-ordering step must match the surface convention TL, TR, BR, BL **as seen in the projector view**.
- The 3 px threshold is the MVP exit criterion (docs/03-roadmap.md §1). If you measure more, the bug is upstream (calibration or compositor); report it in `tasks/BLOCKERS.md` rather than loosening the threshold.
- Keep the e2e test under about 60 s: only 2 s of video at 30 fps.
