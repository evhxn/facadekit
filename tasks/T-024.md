## Goal

HTTP API, prefix `/api/v1`. Errors: HTTP status from `http_status(code)` and body `{"error": {"code": "<CODE>", "message": "<text>"}}`.

| Method and path | Request | Response |
|---|---|---|
| `GET /health` | – | `{"status":"ok","version":"<pkg version>","sim":bool}` |
| `GET /projects` | – | `ProjectSummary[]` |
| `POST /projects` | `{"name": str, "projector": ProjectorSpec}` (`projector` optional) | 201 `Project` |
| `GET /projects/{pid}` | – | `Project` |
| `PUT /projects/{pid}` | `Project` (with the revision it was loaded at) | `Project` (revision + 1) |
| `DELETE /projects/{pid}` | – | 204 |
| `GET /jobs/{jid}` | – | `Job` |
| `POST /jobs/{jid}/cancel` | – | `Job` |

Static files: any path not under `/api` or `/ws` serves the web UI from the package folder `facadekit/webdist/` with `index.html` fallback (single-page app). If `webdist/index.html` does not exist, `GET /` returns a plain-text 200 "FacadeKit backend is running. The web UI has not been built (run `make build-web`)."

CLI:

```
facadekit serve [--host 127.0.0.1] [--port 8137] [--data-dir PATH] [--no-browser] [--sim]
facadekit new   PROJECT_DIR --name NAME [--width 1920] [--height 1080] [--fps 30]
```

Exit codes: 0 success, 1 `FkError` (print `CODE: message` to stderr), 2 usage error.

## Steps

1. `create_app`: build `AppState` (store root = `data_dir/projects` or `projects_dir()`), store it on `app.state.fk`; include routers under `/api/v1`; register an exception handler for `FkError` producing the error body; register a handler for `RequestValidationError` producing code `BAD_REQUEST` (422). Use a `lifespan` context to call `jobs.shutdown()` on exit.
2. `PUT /projects/{pid}`: parse the body with `parse_project`; if `body.id != pid` → `BAD_REQUEST`; `store.save`.
3. Route handlers are plain `def` (sync) so FastAPI runs them in its thread pool; the store does blocking file I/O.
4. Static serving: mount after the API routers. Implement the SPA fallback with a catch-all route that returns the requested file if it exists inside `webdist` (resolve and check it is inside the folder) else `index.html`. Paths starting with `api/` or `ws/` that match nothing must return a JSON 404 with code `NOT_FOUND`, not `index.html`.
5. `serve`: set env `FACADEKIT_DATA` if `--data-dir` is given, then `uvicorn.run(create_app(sim=args.sim), host, port, log_level="info")`. Unless `--no-browser`, open `http://127.0.0.1:<port>/` with `webbrowser.open` from a `threading.Timer(1.0, …)`.
6. `new`: `PROJECT_DIR` must end with `.fkproj` and not exist; create the folder with `media/`, `calibration/`, `renders/`; id = folder stem via `slugify`; write with `save_project_dir`.
7. Wrap CLI command bodies in a helper that converts `FkError` into exit code 1.
8. `client` fixture: `TestClient(create_app(data_dir=tmp_path))` used as a context manager.

## Pitfalls

- Bind to `127.0.0.1` by default. This server has no authentication; do not default to `0.0.0.0`.
- CORS is not needed: in development the Vite dev server proxies `/api` and `/ws`.
- `DELETE` returns an empty 204 body; use `Response(status_code=204)`.

## Acceptance

```
cd studio/backend && uv run pytest -q tests/test_api_projects.py tests/test_cli.py && uv run mypy src && uv run ruff check .
uv run facadekit new /tmp/fk-demo.fkproj --name "Demo" && test -f /tmp/fk-demo.fkproj/project.json
```

Tests: health returns `status ok` and `sim false`; create → 201 with id slug and revision 0; list contains it; get returns it; put with a changed name returns revision 1; put with a stale revision → 409 `REVISION_CONFLICT`; put with a mismatched id → 422; put with an invalid project (clip pointing to a missing surface) → 422 `INVALID_PROJECT`; delete → 204 then get → 404 with the error body shape; `GET /api/v1/nope` → JSON 404; `GET /some/spa/path` → 200 (index or the plain-text notice); `GET /api/v1/jobs/job_missing` → 404; submitting a trivial job through `app.state.fk.jobs` then `GET /jobs/{id}` eventually shows `succeeded`; `facadekit new` twice on the same folder exits 1.
