# T-206 – Wizard: camera check, crop box, plain-language guidance

- **Milestone:** v1.1 camera quality (docs/08 §5)
- **Recommended model:** Sonnet
- **Depends on:** T-204
- **Parallel with:** T-207

## Goal

In the setup wizard, tell the user in plain words whether their camera sees the house well enough, and let them crop to the lit area with one click. When the camera is too coarse, point them to their phone.

## Files to create or modify

- Modify `studio/web/src/pages/SetupPage.tsx` (lift `roi` state next to `cameraId`), `pages/setup/StepCamera.tsx`, `pages/setup/StepScan.tsx`, `pages/setup/StepRealign.tsx`
- Create `studio/web/src/pages/setup/CameraCheckCard.tsx`, `pages/setup/CropBox.tsx`, `pages/setup/cameraCopy.ts` (all user-facing strings), tests `CameraCheckCard.test.tsx`, `CropBox.test.tsx`
- Modify `api/errors.ts` (no new codes in this ticket; reuse existing messages)

## Interfaces available

From T-204: `startCameraCheck(pid, {camera_id, roi})` → `{job_id}`; `waitForJob`; job result `{check: CameraCheck}`; `cameraSnapshotUrl(id, crop?)`. `CalibSettings.roi: CameraRoi | null` ⚑. `Calibration.quality.verdict` ⚑.

## Specification

1. **SetupPage** holds `roi: CameraRoi | null` and `check: CameraCheck | null`. Changing camera resets both. StepScan and StepRealign receive `roi` and send it as `settings.roi` in `startCalibration`.
   - StepScan currently sends `settings = { settle_ms }`; add `roi` when not null.
   - Pi scans (`scan_pi`) ignore it: crop for Pi scans is deferred, so do not send it there.
2. **StepCamera.** Below the live view, a primary button **Check the camera view**. While running, show "Checking… the projector will flash and show stripes for a few seconds." Then render `CameraCheckCard` with the result. A job failure shows the existing `userMessage(code)` in an `ErrorBanner`.
3. **CameraCheckCard.** Copy comes from docs/08 §5, verbatim, kept in `cameraCopy.ts`:
   - Headline from the verdict plus the first reason (`SMALL_IN_FRAME` or `BLURRY`).
   - Extra lines for `NOISY` and `CLIPPED`.
   - The too-coarse details line uses `proj_px_per_cam_px` rounded to a whole number: "Each camera pixel covers about {n} projector pixels."
   - Buttons per verdict as in the table. The first listed button has `className="primary"`.
   - Actions:
     - **Crop to the lit area** sets `roi = check.suggested_roi` (shown only when not null) and opens the CropBox.
     - **Use my phone instead** calls the `onUsePhone` prop. Until T-208, it navigates to the scan step with `?phone=1`; StepScan shows a "coming soon" note for that query (T-208 replaces it).
     - **Scan with this camera**, **Scan anyway** and **Continue** go to the next step.
     - **Check again** re-runs the check, passing the current `roi`.
4. **CropBox.** Overlay on the live view image (same element size).
   - An amber dashed rectangle with four corner handles and draggable edges (pointer events; keyboard: arrow keys move the focused handle by 1 % of the frame, Shift = 5 %).
   - Display coordinates convert to camera pixels using the snapshot's natural size. Round outwards to even integers and clamp to the frame, with a minimum of 64×64 (the same rules as the backend; the backend validates again).
   - Caption: "Only the inside of the box is used. Keep the whole lit area inside the box."
   - Buttons: **Use this crop** (commits to SetupPage), Reset (back to `suggested_roi`), **Use the whole picture** (`roi = null`).
   - After commit, a small zoomed preview uses `cameraSnapshotUrl(id, roi)`.
5. **Pre-fill.** On entering StepCamera with a camera whose latest calibration (`project.calibration_id` → `getCalibration`) has `settings.roi` and `camera_id` equal to the chosen camera, start with that roi. Do not compare with `CameraInfo.width/height`: the listed size can differ from the capture size (T-204 opens at 1920×1080). If a check or scan then fails with the "different camera picture size" message, clear the roi and show that message. Show "Using the crop from your last scan." with a **Use the whole picture** link.
6. **StepScan result screen.** When `calibration.quality?.verdict` is `marginal` or `too_coarse`, add the line "Your camera saw the projection small, so check the outlines carefully on the house." Show `CROP_TOO_TIGHT` as "Part of the lit area touched the edge of your crop. If outlines near the edge look off, make the crop a little bigger."
7. **StepRealign** sends the `roi` of the calibration it compares against (`old` calibration's `settings.roi`), not the wizard state.

## Pitfalls

- No jargon anywhere in the UI. Lint it yourself: grep the new files for `ROI|region|Gray|LSB|skip|homograph|modulation|SNR|verdict|bucket|strategy|decode` in **string literals**. Identifiers may use them; visible text may not.
- The live view image is scaled by CSS. Convert using `naturalWidth/naturalHeight` against the bounding rect, never the CSS size alone.
- The check takes the camera. The live view polling gets 409 while it runs, so pause polling during the check.
- Keep all copy in `cameraCopy.ts` so T-208 and translations reuse it.

## Acceptance

```
cd studio/web && pnpm lint && pnpm typecheck && pnpm test
```

Tests (mock the client):

- A good result shows "Your camera sees the projection clearly." and **Continue**.
- A too-coarse result with `proj_px_per_cam_px: 6.4` shows "about 6 projector pixels", and **Use my phone instead** is the primary button.
- Clicking **Crop to the lit area** then **Use this crop** passes `suggested_roi` to the SetupPage callback.
- CropBox:
  - dragging the bottom-right handle by +10 % of the displayed width on a 1280×720 natural image grows `w` by 128 ± 2 px, and the result is even and clamped;
  - **Use the whole picture** gives null.
- StepScan sends `settings.roi` when set and omits it when null.
- The marginal verdict line appears on the result screen.
- A test asserts that no visible string in `cameraCopy.ts` matches the jargon regex above.

## Out of scope

The phone flow (T-208), backend changes, translations.
