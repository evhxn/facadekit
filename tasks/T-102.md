# T-102 – Interactive timeline with undo/redo

- **Milestone:** v1
- **Recommended model:** Sonnet
- **Depends on:** T-034
- **Parallel with:** T-101, T-104, T-106, T-110

## Goal

Replace the read-only timeline strip with a real timeline: drag clips in time and between layers, trim their ends, snap, zoom, multi-select, and undo/redo for all project edits.

## Files to create or modify

`studio/web/src/pages/arrange/Timeline.tsx` (replaces `TimelineStrip.tsx`), `pages/arrange/timelineMath.ts` (+ test), `pages/arrange/clipOps.ts` (extend, + tests), `state/projectStore.ts` (undo/redo, + tests), `pages/ArrangePage.tsx`.

## Interfaces available

```ts
interface Clip { id; asset_id; generator; surface_id; start_ms; duration_ms; in_offset_ms; loop; fit; opacity; fade_in_ms; fade_out_ms; blend }
interface Track { id; name; clips: Clip[] }            // tracks[0] = bottom layer; clips on one track never overlap
interface Timeline { duration_ms; audio_asset_id; tracks: Track[] }
interface Marker { t_ms: number; kind: "beat" | "downbeat" | "onset" | "user" }      // project.markers
// clipOps.ts (T-034): addClip, updateClip, moveClipToTrack, removeClip, overlaps, findClip
// state/projectStore.ts: { project, update(mutator), saveNow(), dirty }
// Transport (T-034): play(), pause(), seek(tMs), tMs, playing
```

## Specification

1. Layout: time ruler on top, one row per track with the top layer first, clip bars showing a thumbnail and name, playhead line, horizontal scroll, zoom with Ctrl/Cmd + wheel (10 px/s to 400 px/s) centred on the cursor. `timelineMath.ts`: `msToX`, `xToMs`, `snap(ms, candidates, tolerancePx, pxPerMs)`, `rulerTicks(viewStartMs, viewEndMs, pxPerMs)`.
2. Interactions (pointer events with capture):
   - Drag a clip body: moves in time; vertical drag moves between tracks; dropping above the top track creates a new track. Drops that would overlap are rejected (bar turns red while dragging; on release it returns).
   - Drag the left or right edge (6 px handles): trim. Left trim changes `start_ms`, `duration_ms` and `in_offset_ms` together so the content does not slide; minimum duration 100 ms; for non-looping video clips the right edge cannot extend past the source's end.
   - Snap targets: other clips' starts and ends, playhead, time 0, timeline end, and `project.markers`; tolerance 8 px; hold Alt to disable.
   - Click selects; Shift-click adds; drag on empty space draws a selection box; Delete removes selected clips; Ctrl/Cmd+D duplicates the selection directly after itself on a free track.
   - Double-click a clip opens the existing `ClipForm`.
   - Drag an asset from the media library onto a track creates a clip at the drop time on that track (default duration: asset duration or 5 s for images) with `surface_id` = the first surface or `canvas`.
3. `clipOps.ts` additions (pure): `moveClips(project, ids, deltaMs, deltaTracks): boolean` (all-or-nothing), `trimClip(project, id, edge: "start" | "end", newMs, assetDurationMs | null): void`, `duplicateClips(project, ids): string[]`.
4. Undo/redo in the store: keep a stack of project snapshots (max 100). `update(mutator, {coalesceKey?})` pushes a snapshot unless the same `coalesceKey` was used within the last 500 ms (so one drag = one undo step). `undo()`, `redo()`, `canUndo`, `canRedo`. Ctrl/Cmd+Z and Shift+Ctrl/Cmd+Z globally (not when focus is in a text input). Loading a project or receiving a server replacement clears the stacks. Undo restores content but keeps the current `revision` number.
5. During a drag, apply changes to local component state and commit to the store once on release.

## Acceptance

```
cd studio/web && pnpm lint && pnpm typecheck && pnpm test
```

Tests: `snap` picks the nearest candidate within tolerance and returns the input otherwise; `xToMs(msToX(t)) == t`; `moveClips` rejects overlapping moves atomically and creates a track when moving above the top; `trimClip` start-trim keeps `start_ms + duration_ms` constant and shifts `in_offset_ms`; right-trim clamps to the source length for non-looping clips; `duplicateClips` returns new ids with no overlaps; store: three updates then two undos then one redo yields the second state; coalesced updates create one undo step; undo keeps `revision`.

## Out of scope

Waveform (T-103), beat snapping UI (T-105), keyframes, ripple edits, copy/paste between projects.
