# T-006 – Geometry: homographies, aspect and fit

- **Milestone:** MVP

## Goal

Implement the small geometry library that maps rectangular media onto a quadrilateral surface in projector pixel space. Both the renderer and (as a TypeScript mirror) the preview depend on these exact rules.

## Background

A *surface* is a quadrilateral drawn in projector pixels with corners ordered top-left, top-right, bottom-right, bottom-left (TL, TR, BR, BL). Rectangular media is mapped onto it with a homography (3×3 perspective transform). Because the quad is seen in perspective, its true shape is unknown, so each surface stores `aspect` (real width ÷ height) which decides cropping ("fill") or letterboxing ("fit").

## Interfaces (copied from docs/05-interfaces.md)

Conventions: points are `(x, y)` floats, origin top-left; point arrays are `(N, 2)`; homographies are `float64 (3, 3)` mapping source → destination.

## Steps

1. `quad_homography`: build `float32` source and destination arrays and call `cv2.getPerspectiveTransform`; return as `float64`. Raise `FkError("BAD_REQUEST", …)` if the quad does not have 4 points or is degenerate (any three corners collinear: check the absolute cross product of consecutive edges is > 1e-6).
2. `apply_h`: append ones, multiply, divide by the third coordinate.
3. `fit_rects` formulas, with `sa = src_w / src_h` and `ta = surface_aspect`:
   - `fill`: if `sa > ta` the source is too wide: crop width to `src_h * ta`, centred; else crop height to `src_w / ta`, centred.
   - `fit`: if `sa > ta` the content is wider than the surface: `dst_w = 1`, `dst_h = ta / sa`, centred vertically; else `dst_h = 1`, `dst_w = sa / ta`, centred horizontally.
   - Unknown `fit` → `FkError("BAD_REQUEST")`.
4. `M` in `clip_homography` is `[[sx, 0, tx], [0, sy, ty], [0, 0, 1]]` with `sx = (u1-u0)/(x1-x0)`, `tx = u0 - x0*sx` and likewise for y.

## Pitfalls

- The "canvas" surface id is rejected by `Project` validation only inside `project.surfaces`; constructing a standalone `Surface(id="canvas")` must work. If the `Surface` model itself rejects it, do the check in the `Project` validator instead and note that in the pull request (the rule belongs to `Project`).
- Do not normalise or reorder quad corners. The user's order defines orientation (a flipped quad mirrors content on purpose).

## Acceptance

```
cd studio/backend && uv run pytest -q tests/test_geom_homography.py && uv run mypy src && uv run ruff check .
```

Tests:

- `quad_homography(100, 50, q)` maps the four source corners onto `q` within 1e-6 for a non-trivial `q`.
- Identity: quad `((0,0),(100,0),(100,50),(0,50))` gives the identity matrix within 1e-9 after dividing by `h[2,2]`.
- `estimate_aspect` of a 200×100 axis-aligned rectangle is 2.0.
- `fit_rects(1920, 1080, 1.0, "fill")` → src `(420, 0, 1500, 1080)`, dst `(0, 0, 1, 1)`.
- `fit_rects(1920, 1080, 1.0, "fit")` → src `(0, 0, 1920, 1080)`, dst `(0, 0.21875, 1, 0.78125)`.
- `fit_rects(100, 100, 2.0, "fit")` → dst `(0.25, 0, 0.75, 1)`.
- `clip_homography` with `fit="stretch"` equals `quad_homography(src_w, src_h, quad)` up to scale.
- `clip_homography` with `fill`: the centre of `src_rect` maps to the same point as the unit-square centre `(0.5, 0.5)` through `quad_homography(1, 1, quad)`.
- Degenerate quad raises `FkError` `BAD_REQUEST`.
