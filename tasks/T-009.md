`capture_factory` (default: a function that opens `cv2.VideoCapture` with the OS-appropriate backend) exists so tests can inject a fake capture object. `list_cameras` takes the same optional `capture_factory` keyword.

## Steps

1. Backend selection in the default factory: Windows `cv2.CAP_DSHOW`, macOS `cv2.CAP_AVFOUNDATION`, Linux `cv2.CAP_V4L2`; fall back to `cv2.CAP_ANY` if opening fails.
2. `open()`: open, request `CAP_PROP_FRAME_WIDTH/HEIGHT`, set `CAP_PROP_BUFFERSIZE` to 1 (ignore failure), read one frame to learn the true resolution. Failure → `FkError("CAMERA_OPEN_FAILED", "Could not open camera <index>")`.
3. `read()`: call `cap.grab()` then `cap.retrieve()`; on failure retry once, then `FkError("CAMERA_READ_FAILED")`. Callers that need a guaranteed-fresh frame discard several frames themselves (the capture loop does this), so `read()` does not sleep.
4. `set_controls` (each wrapped in try/except, result `True` only if `cap.set` returned true):
   - `auto_exposure`: property `CAP_PROP_AUTO_EXPOSURE`. Value for "manual" is `0.25` on V4L2 and `0` on DSHOW/others; "auto" is `0.75` on V4L2 and `1` elsewhere. Try the platform value first, then the other.
   - `exposure` (0..1): map to `CAP_PROP_EXPOSURE`. On DSHOW the scale is log2 seconds: `value = round(-11 + exposure * 10)` (−11 … −1). On V4L2 it is 100 µs units: `value = round(1 + exposure * 999)`. On macOS return `False` (AVFoundation ignores it).
   - `auto_wb`: `CAP_PROP_AUTO_WB` 1/0. `autofocus`: `CAP_PROP_AUTOFOCUS` 1/0.
5. `list_cameras`: for `i in range(max_index)`: try to open and read one frame; collect `CameraInfo(id=str(i), name=f"Camera {i}", width, height)`; always release. Stop after 2 consecutive failures past the first success (probing missing indices is slow on Windows).
6. `close()` is idempotent.

## Pitfalls

- OpenCV prints warnings for missing devices; that is fine, do not try to silence stderr.
- Never leave a capture open in `list_cameras`; on Windows an open handle blocks the next open.
- These camera-control values are best guesses to be corrected by hardware spike S-3. Keep them in one dict at the top of the module named `_CONTROL_TABLE` so the spike result is a one-place edit.

## Acceptance

```
cd studio/backend && uv run pytest -q tests/test_camera_opencv.py && uv run mypy src && uv run ruff check .
```

Tests use a `FakeCapture` class (methods `isOpened`, `set`, `get`, `grab`, `retrieve`, `read`, `release`) injected through `capture_factory`; no real camera:

- `open()` then `resolution` returns the fake's frame size; `read()` returns a `(H, W, 3)` uint8 array.
- A factory whose capture reports `isOpened() == False` → `FkError` `CAMERA_OPEN_FAILED`.
- `retrieve` failing twice → `FkError` `CAMERA_READ_FAILED`.
- `set_controls(auto_exposure=False, exposure=0.5)` returns a dict with exactly those two keys; values mirror the fake's `set` return value.
- `list_cameras` with a factory that succeeds for indices 0 and 1 only returns two entries and releases every capture it opened.

Manual check (not automated): `uv run python -c "from facadekit.devices.camera_opencv import list_cameras; print(list_cameras())"` on a machine with a webcam.
