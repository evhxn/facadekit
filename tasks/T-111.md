# T-111 – Mesh warp editor and WebGL preview

- **Milestone:** v1
- **Recommended model:** Sonnet
- **Depends on:** T-101, T-110
- **Parallel with:** T-105, T-108, T-109

## Goal

Let users bend a surface by dragging grid points while watching the house, and make the WebGL preview show the bent result.

## Files to create or modify

`studio/web/src/pages/surfaces/MeshEditor.tsx`, `pages/surfaces/meshMath.ts` (+ test), `pages/surfaces/SurfaceCanvas.tsx`, `pages/SurfacesPage.tsx`, `gl/compositor.ts`, `gl/meshGeometry.ts` (+ test).

## Interfaces (copied from docs/05-interfaces.md)

```ts
type Pt = [number, number];
interface Mesh { cols: number; rows: number; offsets: Pt[] }     // cells 1..16 each; (cols+1)*(rows+1) offsets in projector px, row-major
interface Surface { id; name; quad: [Pt, Pt, Pt, Pt]; mask; feather_px; aspect; mesh: Mesh | null }
// gl/homography.ts: quadHomography(1, 1, quad): Mat3 ; applyH(h, [u, v]): Pt
```

Definition (must match the backend): control point `(i, j)` (row `i` in `0..rows`, column `j` in `0..cols`) has unit coordinate `(j / cols, i / rows)`; `base = applyH(quadHomography(1, 1, quad), (u, v))`; `final = base + offset`, with offsets bilinearly interpolated between control points. An all-zero mesh equals no mesh.

Projector live view: `projectorShow({mode: "compositor", project_id})` + `projectorTransport(...)` (existing), or outlines mode.

## Specification

1. Surface panel: "Bend (mesh)" section with a grid-size select (Off, 2×2, 3×3, 4×4, 6×6, 8×8) and "Reset bend". Turning it on creates a zero-offset mesh. Changing the grid size **resamples** the existing offsets to the new grid by bilinear interpolation (`resampleMesh` in `meshMath.ts`) so work is not lost.
2. Mesh edit mode on the canvas: draw the warped grid lines (each cell edge drawn as a straight segment between final control-point positions) and a handle on each control point. Dragging a handle changes its offset; arrow keys nudge the selected handle 1 px (Shift 10 px). Corner control points are draggable too, but a hint says "To move the whole corner, edit the surface corners instead."
3. Moving a quad corner keeps offsets unchanged (they are relative to the base position).
4. A "Test pattern" toggle makes the projector show a checkerboard on the selected surface: implement as a temporary preview-only override in the projector compositor message path if available; if not straightforward, show outlines plus grid lines by extending the `outlines` drawing in the projector page to draw an optional `grid` array of polylines per surface (add an optional field `grid?: Pt[][]` to each surface in the `outlines` message sent via a new optional body field `grids` of `POST /projector/show`; backend change is limited to passing the field through). Choose the outlines+grid approach.
5. `meshMath.ts` (pure): `identityMesh(cols, rows)`, `controlPoint(surface, i, j): Pt` (final position), `setControlPoint(mesh, quad, i, j, finalPos): Mesh` (stores `finalPos − base`), `interpolateOffset(mesh, u, v): Pt`, `resampleMesh(mesh, newCols, newRows): Mesh`, `gridPolylines(surface): Pt[][]`.
6. WebGL preview (`meshGeometry.ts` + compositor): for a surface with a non-zero mesh, draw a tessellated grid instead of one quad: subdivide each mesh cell 4×4, vertex position = `final(u, v)`, and pass `(u, v)` as a vertex attribute. Because positions are no longer a pure homography of `uv`, pass `uv` multiplied by the homography's `w` for perspective-correct interpolation: attribute `a_uvw = (u·w, v·w, w)` where `w` is the third component of `H · (u, v, 1)` before the divide; in the fragment shader `uv = v_uvw.xy / v_uvw.z`. The rest of the shader (fit rectangles, opacity, feather, blending) is unchanged. Surfaces without a mesh keep the existing path.
7. `meshGeometry.ts` exports `buildMeshVertices(surface, subdiv = 4): { positions: Float32Array; uvw: Float32Array; indices: Uint16Array }` (pure, tested).

## Acceptance

```
cd studio/web && pnpm lint && pnpm typecheck && pnpm test
cd studio/backend && uv run pytest -q tests/test_api_projector.py     # after adding the optional `grids` pass-through
```

Tests: `identityMesh(2, 2)` has 9 zero offsets; `setControlPoint` then `controlPoint` round-trips; `interpolateOffset` at a control point equals its offset and halfway between two points equals their mean; `resampleMesh` from 2×2 to 4×4 preserves the offsets at coincident points; `buildMeshVertices` for a zero mesh yields positions equal to `applyH(H, uv)` for every vertex and `(cols·subdiv + 1)·(rows·subdiv + 1)` vertices; turning the mesh on stores a zero mesh; "Reset bend" zeroes offsets; the outlines request includes `grids` when the mesh editor is open.

Add a scene `mesh-bend` to the parity suite (`studio/web/e2e/scenes.ts`, T-037): a checkerboard on a 4×4 mesh with the centre point moved by (25, −15); it must pass with the standard thresholds.

## Out of scope

Automatic mesh from scan data (v2), per-vertex colour/brightness correction, soft-edge blending between projectors.
