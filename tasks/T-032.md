# T-032 – Surface editor

- **Milestone:** MVP
- **Recommended model:** Sonnet
- **Depends on:** T-029, T-031 (for navigation; can be developed in parallel using the store)
- **Parallel with:** T-033, T-034, T-035

## Goal

Let the user mark surfaces (garage door, windows, wall areas) as four-corner shapes on the projector-view photo, adjust them precisely, and see the outlines live on the real house through the projector window.

## Product context

The "projector view" is a photo of the house re-sampled into the projector's pixel grid (for example 1920×1080). Anything drawn at pixel (x, y) on it is exactly where projector pixel (x, y) lands on the house. A surface is a quadrilateral with corners in the order top-left, top-right, bottom-right, bottom-left **as seen on the house**; video is later stretched onto it. Because the scan has small errors, the user fine-tunes corners while looking at the real wall, where the projector draws the same outlines.

## Files to create or modify

Under `studio/web/src/`: `pages/SurfacesPage.tsx`, `pages/surfaces/SurfaceCanvas.tsx`, `pages/surfaces/SurfaceList.tsx`, `pages/surfaces/geometry.ts`, CSS modules, tests `pages/surfaces/geometry.test.ts`, `pages/SurfacesPage.test.tsx`.

## Interfaces available

```ts
// api/types.ts
type Pt = [number, number];
interface Surface { id: string; name: string; quad: [Pt, Pt, Pt, Pt]; mask: Mask | null; feather_px: number; aspect: number; mesh: Mesh | null }
newId(prefix: string): string                         // newId("srf")
// state/projectStore.ts
useProjectStore: { project: Project | null, load(id), update(mutator: (draft: Project) => void), saveNow(), dirty, saving, error }
// api/client.ts
projViewUrl(pid, cid): string                         // PNG, exactly projector.width × projector.height
projectorShow({mode: "outlines" | "blank" | "grid", project_id?, selected_id?}): Promise<ProjectorStatus>   // rejects with ApiError code PROJECTOR_NOT_CONNECTED
projectorStatus(): Promise<ProjectorStatus>
```

Rules: surface id `"canvas"` is reserved (never create it). `aspect` = real-world width ÷ height, > 0. `feather_px` 0–200. Clips reference surfaces by id (`project.timeline.tracks[].clips[].surface_id`).

Aspect estimate (must match the backend): `(|TL−TR| + |BL−BR|) / (|TL−BL| + |TR−BR|)`.

## Specification

Layout: left, a large canvas showing the projector view; right, a panel with the surface list and the selected surface's properties.

**Canvas (`SurfaceCanvas`)**

- Shows the projector-view image fitted to the available area (letterboxed), with zoom (mouse wheel, 1×–8×, centred on the cursor) and pan (drag with middle button or Space + drag). All surface coordinates are stored in projector pixels; convert with one pair of functions `toScreen(pt)` / `toProjector(pt)` in `geometry.ts`.
- Draw each surface: outline (2 px, white with a dark halo for visibility on any photo), translucent fill for the selected one, corner handles (8 px squares; the top-left corner handle is round so orientation is visible), the name at the centre.
- **Add**: toolbar button "Add surface", then click four corners on the photo in the order TL, TR, BR, BL (a hint line shows which corner is next; Esc cancels). After the fourth click the surface is created with `name: "Surface N"`, `aspect: estimateAspect(quad)` rounded to 2 decimals, `feather_px: 0`, `mask: null`, `mesh: null`, and selected.
- **Quick add**: button "Add rectangle" creates a centred rectangle covering 40 % of the frame (useful in manual mode).
- **Edit**: drag a corner handle to move it; drag inside the quad to move the whole surface. Clamp points to `[-200, width + 200] × [-200, height + 200]`.
- **Keyboard** (when a corner or surface is selected and focus is on the canvas): arrow keys move the selected corner (or the whole surface if no corner is selected) by 1 projector pixel, Shift+arrow by 10; Tab cycles corners; Delete removes the surface (after confirm if any clip uses it, and those clips are removed too).
- Coordinates readout of the selected corner in projector pixels.

**Panel (`SurfaceList` + properties)**

- List with select, rename (inline), delete, and reorder is not needed.
- Properties of the selected surface: Name; Aspect (number input, step 0.01, with button "Estimate from shape" and helper text "Real width ÷ height. A 16 ft × 7 ft garage door is 2.29."); Edge softness = `feather_px` slider 0–50; button "Flip horizontally" (swaps TL↔TR and BL↔BR) and "Rotate corners" (cycles corner order by one) to fix orientation mistakes.

**Live outlines on the house**

- Toggle "Show outlines on projector" (default on when the projector is connected). When on, after every change (debounced 60 ms) first make sure the store has saved (`saveNow()`), then call `projectorShow({mode: "outlines", project_id, selected_id})`. Dragging must feel live: during a drag, throttle to one save+show cycle at a time (skip intermediate states, always send the last).
- If the call rejects with `PROJECTOR_NOT_CONNECTED`, turn the toggle off and show a small note "Projector window is not open" with a link to the Setup page.
- When leaving the page, call `projectorShow({mode: "blank"})` (ignore errors).

**Empty and manual states**

- No calibration → message with a link to Setup.
- Manual mode projector view (a grid image) works the same.

All edits go through `useProjectStore.update` (auto-save).

`geometry.ts` exports (pure, unit-tested): `estimateAspect(quad)`, `pointInQuad(pt, quad)`, `hitTestCorner(pt, quad, radius)`, `moveQuad(quad, dx, dy)`, `flipHorizontal(quad)`, `rotateCorners(quad)`, `clampPt(pt, w, h)`, and view transforms `makeView({imgW, imgH, viewW, viewH, zoom, panX, panY}) => { toScreen, toProjector }`.

## Pitfalls

- Mouse coordinates must account for the canvas's CSS size versus backing size (`getBoundingClientRect` and `devicePixelRatio`).
- Do not re-create the `<img>` for the photo on every render; load it once per calibration id.
- Self-intersecting quads (bow-ties) are allowed while dragging but show a red outline and the hint "Corners are crossed".

## Acceptance

```
cd studio/web && pnpm lint && pnpm typecheck && pnpm test
```

Tests:

- `estimateAspect([[0,0],[200,0],[200,100],[0,100]]) === 2`.
- `pointInQuad` true for the centre and false outside, on a perspective trapezoid.
- `flipHorizontal` and `rotateCorners` produce the expected corner orders; `moveQuad` shifts all points.
- `makeView` round trip: `toProjector(toScreen(p))` ≈ `p` for several zoom/pan values.
- Page test with a mocked store containing one surface: pressing ArrowRight with corner 0 selected changes `quad[0][0]` by 1; Shift+ArrowDown changes `quad[0][1]` by 10; "Flip horizontally" swaps corners; deleting a surface used by a clip removes that clip after confirmation; with the outlines toggle on, an edit results in `projectorShow` being called with `mode: "outlines"` and the selected id; a rejected `projectorShow` with code `PROJECTOR_NOT_CONNECTED` turns the toggle off.

Manual check in `--sim` mode: draw the garage door on the simulated facade photo.
