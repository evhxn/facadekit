# T-026 – Projector WebSocket, `WsDisplay`, events socket and projector routes

- **Milestone:** MVP
- **Recommended model:** Sonnet (threading + asyncio; review carefully)

## Goal

Implement the server side of the "projector window": a browser page, fullscreen on the projector, connected by WebSocket. The backend pushes images and drawing commands to it and waits for acknowledgements. Also implement the `/ws/events` broadcast socket the main UI listens on.

### `/ws/events` (UI)

Server → client JSON only:

```json
{"type": "job", "job": { …Job… }}
{"type": "projector", "status": { …ProjectorStatus… }}
{"type": "project", "project_id": "garage-2026", "revision": 4}
```

### `/ws/projector` (projector page)

Only one projector page may be connected; a second connection replaces the first (the first is closed with code 4000).

Client → server:

```json
{"type": "hello", "width": 1920, "height": 1080, "dpr": 1}
{"type": "ack", "seq": 17}
```

Server → client (each message has an increasing integer `seq`):

```json
{"type": "image", "seq": 17, "url": "/api/v1/projector/image/17.png"}
{"type": "blank", "seq": 18}
{"type": "white", "seq": 19}
{"type": "grid", "seq": 20}
{"type": "outlines", "seq": 21, "width": 1920, "height": 1080,
 "surfaces": [{"id": "srf_1", "name": "Garage door", "quad": [[0,0],[1,0],[1,1],[0,1]], "selected": true}]}
{"type": "compositor", "seq": 22, "project_id": "garage-2026"}
{"type": "transport", "seq": 23, "playing": true, "t_ms": 1200, "revision": 4}
```

### HTTP routes (prefix `/api/v1`)

| Method and path | Request | Response |
|---|---|---|
| `GET /projector/status` | – | `ProjectorStatus` |
| `POST /projector/show` | `{"mode": "blank"\|"white"\|"grid"\|"outlines"\|"compositor", "project_id"?: str, "selected_id"?: str}` | `ProjectorStatus`; 409 `PROJECTOR_NOT_CONNECTED` if no page |
| `POST /projector/transport` | `{"project_id": str, "playing": bool, "t_ms": int, "revision": int}` | 204 (relayed as a `transport` message; silently ignored when no page is connected) |
| `GET /projector/image/{seq}.png` | – | `image/png` for an `image` message (kept in memory, only the latest 4) |

`outlines` and `compositor` modes require `project_id`; `outlines` loads the project and sends its surfaces (with `selected` true for `selected_id`).

## Design

```python
class EventHub:                                   # api/ws.py
    def __init__(self) -> None: ...
    def bind_loop(self, loop: asyncio.AbstractEventLoop) -> None: ...
    async def connect(self, ws: WebSocket) -> None: ...     # accept, add, loop until disconnect
    def publish(self, message: dict[str, Any]) -> None: ... # thread-safe; schedules sends on the loop; drops dead sockets

class ProjectorHub:
    def __init__(self, events: EventHub, *, sim_size: tuple[int, int] | None = None) -> None: ...
    def bind_loop(self, loop) -> None: ...
    def status(self) -> ProjectorStatus: ...
    async def connect(self, ws: WebSocket) -> None: ...     # handles hello / ack messages until disconnect
    def send(self, message: dict[str, Any], *, wait_ack: bool, timeout: float = 5.0) -> None: ...
        # thread-safe and blocking: assigns seq, sends on the loop, optionally waits for the ack.
        # FkError PROJECTOR_NOT_CONNECTED / PROJECTOR_TIMEOUT
    def put_image(self, png: bytes) -> int: ...             # stores the PNG under the next seq, returns seq
    def get_image(self, seq: int) -> bytes: ...             # FkError NOT_FOUND

class WsDisplay:                                  # devices/display_ws.py, implements ProjectorDisplay
    def __init__(self, hub: ProjectorHub) -> None: ...
    # size: from hub.status() (width, height); FkError PROJECTOR_NOT_CONNECTED if no page
    # show(image): validate shape == size; cv2.imencode(".png"); seq = hub.put_image(png);
```

## Steps

1. Capture the running loop in the app `lifespan` startup (`asyncio.get_running_loop()`) and call `bind_loop` on both hubs.
2. `ProjectorHub.send` is called from worker threads (jobs) **and** from sync route handlers (thread pool). Use `asyncio.run_coroutine_threadsafe(ws.send_json(msg), loop)` and a `threading.Event` per `seq` stored in a dict; the `connect` coroutine sets the event when the matching `ack` arrives. Never call `send` from the event-loop thread with `wait_ack=True` (it would deadlock); route handlers that need it must be sync `def`.
3. On `hello`: store width = `round(width * dpr)`, height likewise, dpr; publish a `projector` event. On disconnect: clear status, release all waiting events (their waiters then raise `PROJECTOR_NOT_CONNECTED`), publish the event.
4. `POST /projector/show`: send the matching message with `wait_ack=False`, record `mode`.
5. **Sim mode** (`AppState.sim` true): construct `ProjectorHub(events, sim_size=(1920, 1080))`. In this mode `status()` reports connected with that size, `send` is a no-op when no page is connected, and `WsDisplay` is not used (T-027 uses `SimDisplay`). A real page may still connect in sim mode for UI development.
6. Job broadcasting: `JobRunner(on_update=lambda job: events.publish({"type": "job", "job": job.model_dump(mode="json")}))`.

## Pitfalls

- `ws.send_json` from two threads at once can interleave; serialise sends through one `asyncio.Lock` inside the hub coroutine.
- Starlette's `TestClient.websocket_connect` runs the app in another thread with its own loop; make sure `bind_loop` happens in `lifespan` so tests work.
- Keep only the last 4 images (a 1080p PNG pattern is small, but do not grow without bound).

Tests (Starlette `TestClient`):

- No page: `GET /projector/status` → `connected false`; `POST /projector/show {"mode":"white"}` → 409 `PROJECTOR_NOT_CONNECTED`.
- Connect to `/ws/projector`, send `hello` 960×540 dpr 2 → status `connected true`, width 1920, height 1080.
- `POST /projector/show {"mode":"grid"}` → the socket receives `{"type":"grid","seq":…}`.
- `outlines` with a project containing one surface → message lists that surface with `selected` matching `selected_id`.
- `WsDisplay.show`: from a helper thread call `show(np.zeros((1080,1920), np.uint8))`; the test socket receives an `image` message; `GET` its `url` returns PNG bytes decoding to 1920×1080; after the test sends the `ack`, the thread finishes without error. Without an ack (use `timeout=0.3` via a hub parameter) it raises `PROJECTOR_TIMEOUT`.
- Wrong image size → `BAD_IMAGE_SIZE`.
- A second projector connection causes the first to be closed.
- `/ws/events` receives a `projector` event when a page connects, and a `job` event when a job is submitted.
- `POST /projector/transport` → 204 and the page receives a `transport` message.
- App created with `sim=True`: status is connected 1920×1080 with no page.
