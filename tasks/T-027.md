# T-027 – Camera and calibration routes

- **Milestone:** MVP
- **Recommended model:** Sonnet
- **Depends on:** T-009, T-014, T-026
- **Parallel with:** T-025, T-028

## Goal

Expose cameras (list, snapshot, controls) and calibration (start a scan or manual calibration as a job, fetch results and images) over HTTP, including a simulator mode that works without hardware.

## Files to create or modify

- Create `studio/backend/src/facadekit/api/routes_devices.py`, `api/routes_calibration.py`
- Modify `api/deps.py` (add `cameras: CameraManager`, `sim_scene`, `sim_display` to `AppState`), `api/app.py` (wire up)
- Create `studio/backend/tests/test_api_calibration.py`

Routes (prefix `/api/v1`):

| Method and path | Request | Response |
|---|---|---|
| `GET /devices/cameras` | – | `CameraInfo[]` (in sim mode exactly one entry: id `"sim"`, name `"Simulated camera"`, 1280×720) |
| `GET /devices/cameras/{cid}/snapshot.jpg` | – | `image/jpeg` current frame |
| `POST /devices/cameras/{cid}/controls` | `{"auto_exposure"?: bool, "exposure"?: number, "auto_wb"?: bool, "autofocus"?: bool}` | `{"applied": {…: bool}}` |
| `POST /projects/{pid}/calibrations` | `{"mode": "scan"\|"manual", "camera_id"?: str, "settings"?: CalibSettings}` | 202 `{"job_id": str}`; on success the server sets `project.calibration_id` and bumps the revision |
| `GET /projects/{pid}/calibrations/{cid}` | – | `Calibration` |
| `GET /projects/{pid}/calibrations/{cid}/proj_view.png` | – | `image/png` |
| `GET /projects/{pid}/calibrations/{cid}/measured_mask.png` | – | `image/png` (404 in manual mode) |

Job result for calibration: `{"calibration_id": str}`. After success also publish `{"type": "project", "project_id": pid, "revision": <new revision>}` on the event hub.

## Design

```python
class CameraManager:                          # in routes_devices.py or a small api/cameras.py
    """Owns at most one open camera at a time and serialises access with a lock."""
    def __init__(self, *, sim_camera_factory: Callable[[], Camera] | None = None) -> None: ...
    def list(self) -> list[CameraInfo]: ...
    def snapshot(self, camera_id: str) -> np.ndarray: ...        # opens if needed, keeps it open for 10 s of idle
    def set_controls(self, camera_id: str, **controls) -> dict[str, bool]: ...
    def acquire(self, camera_id: str) -> Camera: ...             # closes any preview camera and returns a fresh, unopened Camera for a job
```

## Steps

1. Camera ids: `"sim"` (only in sim mode) or a decimal OpenCV index. Anything else → `NOT_FOUND`.
2. Snapshot: JPEG quality 80 via `cv2.imencode`; add header `Cache-Control: no-store`. The UI polls this about 3 times per second for the live view, so keep the camera open between calls and close it after 10 s without requests (check lazily on the next call or with a `threading.Timer`).
3. Starting a scan (`mode="scan"`): `camera_id` required (`BAD_REQUEST` otherwise). Real mode: require a connected projector (`PROJECTOR_NOT_CONNECTED`) and check its reported size equals the project's projector size (`RESOLUTION_MISMATCH`, message as in T-011) **before** submitting the job. Display = `WsDisplay(state.projector)`. Sim mode: display = the shared `SimDisplay`, camera = `SimCamera(scene, display)`, and pass `sleep=lambda s: None`.
4. Job function: call `run_calibration`, then load the project, set `calibration_id`, `store.save` (retry once on `REVISION_CONFLICT` after reloading), publish the `project` event, return `{"calibration_id": id}`.
5. `mode="manual"`: same job flow using `create_manual_calibration`.
6. Image routes: `FileResponse` from `calibration/<cid>/…`; missing file → `NOT_FOUND`.
7. While a scan job runs, `snapshot` for the same camera must not open a second handle: `acquire` marks the camera busy and `snapshot` returns HTTP 409 with code `BAD_REQUEST` and message "Camera is busy scanning" until the job releases it (release in a `finally`).

## Pitfalls

- In sim mode the simulated projector is 1920×1080; if the project uses another resolution return `RESOLUTION_MISMATCH` just like real mode.
- Do not hold the `CameraManager` lock while a job runs for 30 s; hold only a "busy" flag.
- The job thread calls `WsDisplay.show` (blocking on acks). That is why calibration runs in the job runner and never in a request handler.

## Acceptance

```
cd studio/backend && uv run pytest -q tests/test_api_calibration.py && uv run mypy src && uv run ruff check .
```

Tests use `TestClient(create_app(data_dir=tmp_path, sim=True))`:

- `GET /devices/cameras` → one camera with id `sim`.
- `GET /devices/cameras/sim/snapshot.jpg` → JPEG bytes decoding to 1280×720. Unknown id → 404.
- `POST …/controls {"auto_exposure": false}` → `{"applied": {"auto_exposure": true}}`.
- Create a project, `POST /calibrations {"mode":"scan","camera_id":"sim","settings":{"discard_frames":0,"average_frames":1}}` → 202; poll `GET /jobs/{id}` until `succeeded` (timeout 60 s); then the project has `calibration_id` set and a higher revision; `GET` calibration returns `mode == "scan"` with `quality.coverage > 0.85`; `proj_view.png` and `measured_mask.png` return PNGs.
- `mode="manual"` → job succeeds; `measured_mask.png` → 404.
- `mode="scan"` without `camera_id` → 422.
- Project created with projector 1280×720 → `RESOLUTION_MISMATCH` (500-class mapping is acceptable; assert on the error code in the body).
- App with `sim=False` and no projector page: scan request → 409 `PROJECTOR_NOT_CONNECTED`.
