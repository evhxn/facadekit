Give the tests realistic "camera far from the house" and "phone with zoom" scenes, so the crop and quality features can be tested without hardware.

## Specification

Add to `sim/scene.py`:

SCENE_FAR_TOO_COARSE = lambda: far_scene(0.28)

Write the three presets as plain functions (`def scene_far_marginal() -> SimScene:` etc.), not lambdas, to satisfy ruff. Compute the Jacobian numerically (central differences of `apply_h` with step 0.5 px) or analytically. Both are fine.

## Steps

1. Implement the functions above with type hints and docstrings.
2. Tests (`test_sim_far.py`):
   - `default_scene()` renders byte-identically before and after this change. Compare `render_camera(white, rng(0))` against a hash computed in the test from a fresh `SimScene()`. The point: neither the default nor `SimScene` was touched.
   - `scale_world(default_scene(), 2.0).h_p2c` equals `default_scene().h_p2c` within 1e-9 (relative).
   - `true_px_per_proj_px`: default in [0.40, 0.55], marginal in [0.22, 0.34], too coarse in [0.11, 0.16], phone ≥ 0.55. Print the actual values in the test output (`-s`) and copy them into the PR description.
   - For each preset, the four projector corners mapped through `h_p2c` lie inside the camera frame.
   - Too-coarse preset: render BLACK and WHITE with noise; the old lit rule (`contrast > max(12, 0.15·p95)`) gives a lit fraction < 0.05 (proves the old gate would refuse it).

## Pitfalls

- `SimScene` caches the albedo in `init=False` fields; `dataclasses.replace` re-runs `__init__`, which resets them. Do not copy them by hand.
- `world_corners_cam` must stay a tuple of 4 tuples of Python floats (not NumPy scalars) so `repr` and equality behave.
- Rendering the phone preset at 2560×1440 with a 3200×1800 world takes about 0.3 s per frame; keep tests to a handful of renders.
