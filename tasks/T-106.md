## Goal

Given the projector-view photo and a few user clicks ("this is the object" / "this is not"), return the object's outline as a polygon and a best-fit four-corner quad, so users can create a surface with one click.

## Files to create or modify

- Create `studio/backend/src/facadekit/ai/segment.py`, `tests/test_ai_segment.py`
- Modify `api/routes_ai.py` (create it if T-104 has not), `api/app.py`

Route (prefix `/api/v1`): `POST /projects/{pid}/segment` with `{"points": [{"x": number, "y": number, "label": 0|1}], "prefer"?: "auto"|"mobilesam"|"grabcut"}` → `{"outer": Point[], "quad": Point[], "score": number, "engine": "mobilesam"|"grabcut"}`. Uses `calibration/<calibration_id>/proj_view.png` of the project (`BAD_REQUEST` if the project has no calibration; at least one label-1 point required).

## Steps

1. `mask_to_polygon_and_quad(mask)` (mask: bool or uint8 `(H, W)`): keep the largest connected component; fill holes (`cv2.findContours` with `RETR_EXTERNAL`); polygon = `cv2.approxPolyDP(contour, 0.004 * perimeter, True)` (cap at 64 points by increasing epsilon). Quad: try `approxPolyDP` with epsilon from 1 % to 8 % of the perimeter until exactly 4 points; if never 4, use `cv2.boxPoints(cv2.minAreaRect(contour))`. Order the quad TL, TR, BR, BL: sort by angle around the centroid, then rotate so the first point is the one with the smallest `x + y`. Empty mask → `FkError("BAD_REQUEST", "Nothing was selected")`.
2. `GrabCutSegmenter`: downscale the image so the long side is ≤ 800 px. Build the GrabCut mask: everything `GC_PR_BGD`; a disc of radius 2 % of the image diagonal around each include point = `GC_FGD`, plus a larger disc (12 %) around the first include point = `GC_PR_FGD`; exclude points = `GC_BGD` discs. Run `cv2.grabCut(..., 5, cv2.GC_INIT_WITH_MASK)`. Result mask = `GC_FGD | GC_PR_FGD`, upscaled with nearest neighbour. `score = 0.5`.
3. `MobileSamSegmenter` (ONNX Runtime, CPU): `set_image` resizes the long side to 1024, converts BGR→RGB, normalises with mean `[123.675, 116.28, 103.53]` and std `[58.395, 57.12, 57.375]`, pads to 1024×1024, runs the encoder once and caches the embedding. `segment` runs the decoder with `point_coords` (scaled to the 1024 frame, plus the padding point `(0,0)` with label `-1`), `point_labels`, `mask_input` zeros `(1,1,256,256)`, `has_mask_input` `[0]`, `orig_im_size`; threshold the returned mask at 0; `score` = the returned IoU prediction. Follow the exact tensor names recorded in `spikes/S-6-mobilesam.md` if they differ.
4. `get_segmenter("auto")`: try MobileSAM (import `onnxruntime`, `ensure_model` both files); on `ImportError` or `FkError` fall back to GrabCut. Cache one segmenter and its image embedding per `(project_id, calibration_id)` in `AppState` so repeated clicks are fast.
5. The route is sync `def` (CPU-bound, runs in the thread pool). The first MobileSAM call may download models; the UI shows a spinner (T-108).

Tests (no model download in CI; MobileSAM tests are marked `@pytest.mark.models` and skipped unless env `FK_TEST_MODELS=1`):

- `mask_to_polygon_and_quad` on a synthetic filled quadrilateral mask returns a quad whose corners are within 3 px of the true corners, ordered TL, TR, BR, BL; on a filled circle returns 4 points (min-area-rect path) and a polygon with ≥ 8 points; empty mask → `BAD_REQUEST`.
- GrabCut on the simulator's projector-view-like image (use `default_scene().albedo()` warped to projector space with `inv(h_p2w)`): one include click at the garage-door centre returns a quad with IoU > 0.8 against the true door quad.
- Route: project with a scan calibration in sim mode; `POST /segment` with `prefer: "grabcut"` and the door-centre point returns `engine == "grabcut"` and 4 quad points; no calibration → 422; no include point → 422.
