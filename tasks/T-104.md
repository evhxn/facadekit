# T-104 – Beat and onset detection (backend)

- **Milestone:** v1
- **Recommended model:** Sonnet
- **Depends on:** T-025, T-023
- **Parallel with:** T-101, T-102, T-106, T-110

## Goal

Analyse the show audio and store beat and onset markers in the project so the timeline can snap to the music.

## Files to create or modify

- Create `studio/backend/src/facadekit/ai/beats.py`, `api/routes_ai.py`, `tests/test_ai_beats.py`
- Modify `api/app.py` (include router)

## Interfaces (copied from docs/05-interfaces.md)

```python
class Marker(BaseModel):                     # facadekit.models.project
    t_ms: int
    kind: Literal["beat", "downbeat", "onset", "user"]

def analyze_beats(audio_path: Path) -> list[Marker]      # kinds "beat" and "onset"; FkError AI_UNAVAILABLE if librosa is not installed
```

Route (prefix `/api/v1`): `POST /projects/{pid}/assets/{aid}/analyze` → 202 `{"job_id": str}`. Job kind `"analyze"`, result `{"markers": int}`. The job replaces all non-`user` markers in `project.markers` with the new ones (sorted by `t_ms`), saves the project (retry once on `REVISION_CONFLICT`), and publishes `{"type": "project", "project_id", "revision"}` on the event hub.

Available: `AppState.store` (`load`, `save`, `project_dir`), `AppState.jobs.submit(kind, fn)`, `AppState.events.publish(dict)`, `facadekit.media.ffmpeg.run_ffmpeg(args)`, `FkError`.

## Steps

1. `librosa` is in the optional extra `ai`. Import it inside `analyze_beats`; `ImportError` → `FkError("AI_UNAVAILABLE", "Beat detection needs the optional 'ai' components. Install with: pipx inject facadekit librosa")`.
2. Decode to a temporary mono 22050 Hz WAV with the bundled ffmpeg first (`run_ffmpeg(["-y", "-i", src, "-ac", "1", "-ar", "22050", tmp_wav])`) so librosa never needs system codecs; load with `librosa.load(tmp_wav, sr=None)`.
3. Beats: `tempo, frames = librosa.beat.beat_track(y=y, sr=sr)`; times via `librosa.frames_to_time`. Onsets: `librosa.onset.onset_detect(y=y, sr=sr, backtrack=False, units="time")`. Drop onsets within 40 ms of a beat (the beat wins). Convert to integer ms.
4. Asset must be audio, or a video with `has_audio` (else `BAD_REQUEST`).
5. Report coarse progress: 0.1 after decode, 0.6 after beats, 0.9 after onsets.

## Pitfalls

- First import of librosa/numba is slow (several seconds); that is why this runs as a job.
- Very long files: cap analysis at the first 15 minutes (`-t 900` in the ffmpeg call).

Route test: upload the WAV, call analyze, wait for the job, and the project's `markers` list is non-empty and sorted; a pre-existing `user` marker survives; analysing an image asset → 422. With `librosa` import monkeypatched to fail → job fails with `AI_UNAVAILABLE`.
