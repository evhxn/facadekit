# T-035 – Publish page (render and send to FPP)

- **Milestone:** MVP
- **Recommended model:** Sonnet
- **Depends on:** T-029
- **Parallel with:** T-031, T-032, T-033, T-034

## Goal

Build the last step of the workflow: render the show to a video file, connect to the user's Falcon Player (FPP), upload, create the playlist, start it, and offer the "alignment check" video.

## Product context

FPP is the free show player running on the user's Raspberry Pi (usually reachable as `fpp.local` or an IP address). FacadeKit renders an MP4 whose pixels are already warped for the projector, uploads it to FPP, and creates a playlist. For the show the projector's HDMI cable must be plugged into the Pi instead of the laptop. An "alignment check" is a 20-second video of the surface outlines; if those outlines sit on the real garage door when played from the Pi, the show will line up too.

## Files to create or modify

Under `studio/web/src/`: `pages/PublishPage.tsx`, `pages/publish/RenderPanel.tsx`, `pages/publish/FppPanel.tsx`, CSS modules, tests `pages/PublishPage.test.tsx`.

## Interfaces available (T-029)

```ts
startRender(pid, {preset: string, include_audio: boolean, kind: "show" | "alignment_check"}): Promise<{job_id: string}>
listRenders(pid): Promise<RenderInfo[]>            // {render_id, filename, size_bytes, modified_at}, newest first
renderFileUrl(pid, rid): string
fppProbe(host): Promise<FppProbe>                  // {reachable, version, major, ok, problems: string[]}
fppStatus(host): Promise<FppStatus>                // {status_name, current_playlist, seconds_played} (nulls when unreachable)
publish(pid, {host, render_id, playlist_name?, start: boolean}): Promise<{job_id: string}>
waitForJob(jobId, onUpdate?): Promise<Job>         cancelJob(id): Promise<Job>
userMessage(code, fallback): string
useProjectStore: { project, update(mutator), saveNow(), load(id) }
// components from T-031: JobProgress({job, onCancel}), ErrorBanner({message, actions?})
```

Presets (ids are fixed by the backend): `pi3-1080p30` (default; label "Raspberry Pi – best quality (1080p)"), `pi3-720p30` (label "Raspberry Pi – lighter (720p). Use if playback stutters."), `preview-540p` (label "Quick preview (low quality)").

Job results: render `{render_id, filename, size_bytes, duration_ms}`; publish `{media_name, playlist_name, started}`. After a successful publish the server stores `host` in `project.fpp.host` (reload the project).

## Specification

**Render panel**

- Preset select (default `pi3-1080p30`), checkbox "Include audio" (default on, disabled with a note if the timeline has no audio), button "Render show".
- Clicking it: `saveNow()`, `startRender`, show `JobProgress` with Cancel; on success refresh the render list and select the new render. Failure → `ErrorBanner` with `userMessage`.
- Render list: file name, size in MB, date, a "Preview" link (opens `renderFileUrl` in a new tab) and a radio button to choose which render to publish (newest selected by default).
- Before rendering, show warnings (non-blocking): no clips on the timeline ("The show is empty."); no surfaces; project has no calibration.

**FPP panel**

- Host input (prefilled from `project.fpp.host`, placeholder `fpp.local`) and "Connect" button → `fppProbe(host)`.
  - Not reachable or not ok → list `problems` in an `ErrorBanner`.
  - OK → "Connected to FPP {version}". Store the host with `store.update(d => { d.fpp.host = host })`.
- Playlist name input, default `FacadeKit - <project name>` (send `playlist_name` only if the user changed it).
- Checkbox "Start playing now" (default on).
- Button "Send to FPP" (enabled when connected and a render is selected) → `publish` → `JobProgress` → success message "Sent. Playlist “{playlist_name}” is on your FPP." plus a reminder box: "Move the projector's HDMI cable from this computer to the Raspberry Pi."
- Status line polling `fppStatus(host)` every 3 s while the page is visible and connected: "FPP is playing {current_playlist}" / "FPP is idle".

**Alignment check**

- A separate box: "Check alignment from the Pi". Button "Render and send alignment check" runs: `saveNow()` → `startRender({preset: "pi3-1080p30", include_audio: false, kind: "alignment_check"})` → wait → `publish({host, render_id, start: true})` → wait. Shows progress for both stages.
- After success show: "Look at the house. The outlines should sit exactly on your surfaces. If they are shifted, set FPP's HDMI output to the projector's native resolution, turn off overscan on the projector, then try again."

## Pitfalls

- Stop polling `fppStatus` when the tab is hidden (`document.visibilityState`) and on unmount.
- Do not send `host` values with `http://`; strip the scheme and trailing slash client-side before probing.
- A cancelled job has state `cancelled`, not an error: show nothing alarming.

## Acceptance

```
cd studio/web && pnpm lint && pnpm typecheck && pnpm test
```

Tests (API mocked):

- "Render show" calls `saveNow` then `startRender(pid, {preset: "pi3-1080p30", include_audio: true, kind: "show"})`; a succeeded job leads to `listRenders` being called again and the new render selected.
- Failed render with code `FFMPEG_FAILED` shows an error banner.
- Typing `http://fpp.local/` and clicking Connect calls `fppProbe("fpp.local")`; a probe with `ok: false, problems: ["FPP 9.4 is too old…"]` shows that text and keeps "Send to FPP" disabled; `ok: true` enables it.
- "Send to FPP" calls `publish(pid, {host: "fpp.local", render_id: <selected>, start: true})` without `playlist_name` when unchanged, and with it when edited.
- After a succeeded publish the HDMI reminder text is visible.
- The alignment-check button triggers `startRender` with `kind: "alignment_check"` and then `publish` with the returned `render_id`.

Manual check: with `facadekit serve --sim` and a fake FPP (see `facadekit/fpp/fake.py`; run it with `uvicorn` on port 8090) complete a render and publish to `127.0.0.1:8090`.
